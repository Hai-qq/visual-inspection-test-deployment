# Visual Inspection Test Deployment v0.6.0 ONNX YOLO 端到端推理验收说明

## 1. 验收结论范围

本版本用于验收“配置 → 文件夹取图 → 真实 ONNX Detection 或确定性清单分析 → 检测框空间筛选 → 测试序列 → 规则/姿态判定 → 同屏结果/统计 → 日志”的本地闭环。内置通过/不通过图片和 `detections.json` 仍可在没有模型或相机时复现；满足现役张量契约的 ONNX 模型则优先执行真实 CPU 推理。

仓库的 `v1.0.0` 标签冻结本说明对应的旧版功能基线（应用程序集版本 v0.6.0）。当前 `agent/v2-wizard-ui` 分支额外提供 Test Sequence Setting V2 前端评审原型；该原型不读写配置，不属于下列 v0.6.0 功能验收结论。V2 界面评审使用本章新增的 AC-V2-UI-01。

本版本可以验收：

- 操作工工作台三栏同屏布局与施耐德风格浅色视觉；
- 管理员文件夹图源选择、策略、校验、预览和保存；
- 管理员测试序列设置的七个配置分区及校验保存；
- ONNX `names`、`labels`、`class_names`、`classes` 标签元数据读取、失败提示和手工修正入口；
- 静态 `Float[1,3,H,W]` 输入、端到端 `Float[1,N,6]` 输出的真实 ONNX Detection CPU 推理；
- Letterbox/RGB/0–1 预处理、原图坐标还原、Class ID 到 Target/Model Binding 显式映射以及模型契约门禁；
- 模型与标签、目标主绑定、普通规则、逻辑关系、阈值和延时编辑；
- 全图/ROI 切换、坐标填写及图像鼠标框选 ROI；
- 姿态步骤画布、步骤参数、新增、删除和顺序调整；
- 中文登录窗口、本地账户验证和管理员/操作员界面隔离；
- PBKDF2-SHA256 密码哈希、错误密码拒绝和禁用账户门禁；
- 测试序列逐项执行、默认/单项延时、开始/停止/复位；
- 纯普通检测项的 Folder Test Sequence 一次启动后遍历全部图片；每张图片执行完整普通序列并作为一个会话统计对象，同图多个普通项只执行一次模型分析；
- 普通数量规则、同帧多规则和 AND/OR 引擎；
- Detection 按目标、模型绑定和置信度筛选，Full Image/ROI 按框中心点实际计数；
- ROI 参考尺寸缩放、多 ROI 并集去重，以及 ROI/检测框/目标名/置信度同图叠加；
- 固定线性姿态动作顺序、连续保持和等待超时；
- 当前图片、ROI、标准、实测值、逐项状态和总体结果；
- “当前会话”的通过/不通过/错误、数量/比率视图；
- 操作工工作台、管理员图源页、示例数据、状态、日志和错误提示均使用简体中文；
- JSON 配置、JSONL 运行日志和端到端冒烟回执；
- 缺少受支持模型和验收清单时的明确运行门禁。

本版本不能作为以下项目的验收证据：PT 推理或标签安全提取、动态输入、原始 YOLO `[1,C,N]` 输出与外置 NMS、Classification、Segmentation、Pose/Temporal 真实推理、通用模型精度、DirectShow、工业相机 SDK、生产账户增删/改密/外部身份源、测试序列新建/复制、正式发布/回退、历史查询、叠加层开关、姿态关键点绘制和正式品牌规范。这些能力仍在需求基线中，但不伪装为已完成。

## 2. 运行条件与入口

- Windows x64；
- .NET 8 Desktop Runtime；
- 发布程序由 C#/.NET 8 WPF 解决方案构建；PowerShell 脚本只编排测试与发布，不属于产品实现；
- 默认 Release：`artifacts\acceptance-zh-CN\VisualInspection.App.exe`。
- 可复制包：`artifacts\VisualInspection-v0.6.0-onnx-yolo-e2e-zh-CN-win-x64.zip`。

本地验收账户：

| 角色 | 用户名 | 密码 | 预期入口 |
| --- | --- | --- | --- |
| 管理员 | `admin` | `Admin@123` | 测试执行、统计、测试序列设置、图源设置 |
| 操作员 | `operator` | `Operator@123` | 仅测试执行与统计 |

固定密码只用于本地验收。账户文件位于 `%LocalAppData%\VisualInspectionTestDeployment\users\users.json`，其中不保存明文密码。

首次启动会创建：

```text
%LocalAppData%\VisualInspectionTestDeployment\projects\00000000000000000000000000000001.json
%LocalAppData%\VisualInspectionTestDeployment\acceptance-data\sample-set-01\
%LocalAppData%\VisualInspectionTestDeployment\acceptance-data\sample-set-fail\
```

每组内置数据含 12 张 640 × 360 BMP。第 1–3 张分别用于螺钉、标签和表面瑕疵项；第 4–12 张以每 3 帧一个动作的方式模拟拿取、放置、确认。默认 `sample-set-01` 为全通过；`sample-set-fail` 在第 3 帧提供一个表面瑕疵，使第三项和整体运行不通过。

## 3. 人工验收步骤

### AC-MVP-01 启动与同屏布局

1. 启动 `VisualInspection.App.exe`。
2. 使用管理员验收账户登录并确认没有错误弹窗。
3. 查看主窗口。

预期：

- 左侧为 4 项测试序列和“开始测试/停止/复位”；
- 中部显示内置首帧、当前项标准、实测区和结果；
- 右侧“全局统计”始终可见；
- 顶栏图源为“文件夹”且显示“就绪”；
- 状态栏显示验收清单适配器已就绪，“开始测试”可点击；
- 底部显示“实时日志”和本机日志路径。

### AC-MVP-02 管理员文件夹图源设置与预览

1. 点击顶栏“图源设置”。
2. 选择“文件夹图源”。
3. 点击“使用内置通过数据”。
4. 点击“校验图源”。

预期：显示第一张图片；校验文本包含“12 个文件”、“640 × 360”和“已找到 detections.json”。更改递归、排序、坏图策略、循环或姿态帧间隔后点击“保存图源”，主窗口重新载入配置。

### AC-MVP-03 完整通过流程

1. 在主窗口点击“开始测试”。
2. 观察左侧项目、中部图片与底部日志，等待约 2 秒。

预期：

| 顺序 | 项目 | 标准 | 预期实测 |
| ---: | --- | --- | --- |
| 1 | 螺钉在位 | ROI 中数量 `= 4` | `螺钉=4`，通过 |
| 2 | 标签对齐 | 全图数量 `= 1` | `标签=1`，通过 |
| 3 | 表面瑕疵 | 数量 `> 0` 时不通过 | `表面瑕疵=0`，通过 |
| 4 | 动作序列 | 拿取 → 放置 → 确认 | 三步依次确认，通过 |

最终结果为“通过”；右侧“有效总数”和“通过”各增加 1，“错误”不变。再次执行后两项各再增加 1，证明统计对象是完整测试运行，而不是测试项。

### AC-MVP-04 不通过场景与数量/比率统计

1. 完成一次通过运行。
2. 打开“图源设置”，点击“使用内置不通过数据”，校验后保存。
3. 再执行一次测试运行。
4. 在右侧选择“比率”，再切回“数量”。

预期：第三项“表面瑕疵”实测为 1 并不通过，整体不通过；“当前会话”的有效总数=2、通过=1、不通过=1。数量模式的横向数量条和下方紧凑饼图均显示 1:1 分布；切换到比率模式后，大型圆环显示 50.0%。错误独立显示，不进入饼图、圆环或比率分母；无有效结果时饼图显示中性空状态、比率显示 `--`。完成后在“图源设置”中选择“使用内置通过数据”恢复基线。

### AC-MVP-05 Stop 与 Reset

1. 开始测试后在姿态图片播放阶段点击“停止”。
2. 点击“复位”。

预期：停止请求取消后，已完成项保留，当前项为“已停止”，未执行项保持“待执行”；本次已停止运行不增加通过/不通过/错误。复位将项目恢复为“待执行”，但不清除已经完成的会话统计。

### AC-MVP-06 模型运行门禁

1. 在当前项目中把所有启用规则所引用的 ONNX 文件临时改为不存在路径或不受支持的输出契约。
2. 打开“图源设置”，选择一个存在且含可读图片、但不含 `detections.json` 的文件夹，校验并保存。

预期：首帧预览成功；校验信息同时说明 ONNX 契约不可用且没有 `detections.json`；返回主界面后“开始测试”禁用，不会使用不存在或结构不匹配的模型产生虚假结果。恢复有效 ONNX 路径，或使用内置通过数据，可恢复 Ready。

### AC-MVP-07 相机适配门禁

1. 打开“图源设置 > 相机图源”。
2. 查看或保存 DirectShow/Vendor 配置。

预期：页面明确显示“适配器尚未安装”；保存后主界面显示“不可用/已阻止”，“开始测试”禁用，不会伪报相机已连接。返回文件夹图源页并使用内置数据可恢复。

### AC-MVP-08 运行日志

1. 完成一次 Run。
2. 打开底部显示的 JSONL 路径。

预期：界面日志显示中文运行消息；JSONL 文件包含运行开始、测试项开始、采集帧、测试项完成和运行完成等结构化事件，业务不通过与系统错误使用不同的判定值和级别。

### AC-MVP-09 管理员测试序列设置

本项适用于 `v1.0.0` 标签或既有 v0.6.0 正式验收包。V2 前端分支中的主入口已切换为不保存的向导原型。

1. 在管理员登录后的工作台顶部点击“测试序列设置”。
2. 依次查看“常规、模型与标签、目标与绑定、规则与 ROI、姿态序列、输入源、用户与权限”。
3. 在“常规”中修改默认延时，点击“校验并保存”，再重新打开窗口核对。

预期：七个分区均可显示；配置保存后主工作台自动重载；再次打开时默认延时为保存后的值。完成验收后可恢复为 100 毫秒。

### AC-MVP-10 规则、ROI 与姿态画布

1. 在“规则与 ROI”中选择“螺钉在位”，确认目标、模型绑定、在场数量、等于 4、条件成立时通过等字段已回填。
2. 点击“新增检测项”，确认列表选中新建的“普通检测项 1”，并已自动填入一条全图、在场数量等于 1、成立时通过的默认规则；点击“删除检测项”恢复原序列。Classification 绑定应改用“是否存在等于 1”的默认规则。
3. 将“螺钉在位”的区域切换为 ROI，在预览图上拖动框选，确认 X1/Y1/X2/Y2 随鼠标更新；点击“应用规则”。
4. 在“姿态序列”中查看“拿取 → 放置 → 确认”动作画布；选择步骤后检查动作条件、模型绑定、保持时间和最大等待时间。
5. 如测试上移/下移，执行相反操作恢复原顺序后再保存。

预期：新增普通检测项立即具有可编辑、可校验的默认规则；删除后剩余测试项顺序连续，且不能删除序列中的最后一个测试项。ROI 坐标与画布一致且通过配置边界校验；姿态画布按步骤顺序更新；保存后操作员工作台显示最新标准，完整内置通过流程仍可正常执行。

### AC-V2-UI-01 Test Sequence Setting 顺序向导前端

1. 在当前 V2 分支执行 `dotnet run --project src\VisualInspection.App\VisualInspection.App.csproj -- --v2-wizard-preview`，或以管理员进入工作台并点击“测试序列设置 V2”。
2. 确认顶部显示项目信息、选择图源、导入模型、编排检测项、检测内容、判定条件、运行参数、检查完成 8 个步骤；步骤数量不是固定的 5。先直接点击“导入模型”，确认“项目信息”和“选择图源”仍为待设置、不会跟着变绿；返回第 1 步并顺序点击下一步，确认只有刚通过必填校验的步骤显示已完成。进入“选择图源”，依次点击图片文件夹、USB 摄像头和工业相机卡片的空白区域，确认整卡可选且只有当前卡变为浅绿背景和深绿边框。
3. 进入“导入模型”，确认左侧同时显示多个模型，点击“添加模型”后新增一张模型卡；在右侧修改该模型的名称和任务类型，确认其他模型数据不变，再用减号删除新模型。悬停加减按钮和字段信息图标时应显示中文 ToolTip。
4. 进入“编排检测项”，确认列表按 `01、02、03` 排序，每项同时显示“目标检测/姿态动作”和“必选项/可选项”；“绑定模型”下拉框应显示第 3 步模型库中的全部模型。点击加号新增一项，用上下按钮调整顺序，再用减号删除，确认编号连续。
5. 在右侧把当前项从“目标检测（单张图）”切换为“姿态动作（连续帧）”，并切换必选状态；确认所有必填字段旁显示红色 `*`，悬停信息、加号、减号和排序图标时显示中文 ToolTip。
6. 点击下一步，确认姿态项只显示有序动作画布、动作加减和排序；判定条件只显示保持时间和等待超时。修改当前动作、保持时间和等待超时，确认下方“最终判定”逐项同步。改回目标检测后，应只显示标签、全图/ROI 和数量规则。
7. 在目标判定条件中依次选择“数量等于、数量范围、数量大于”并修改数值，确认下方“最终判定”同步目标标签、区域、比较方式和数值；选择数量范围时应出现最大数量输入。输入最小值 5、最大值 2，确认显示范围错误且下一步被阻止，再改为有效范围。
8. 在“检测内容”保持目标检测和 ROI，点击“重新框选区域”，然后在右侧预览内按住鼠标左键拖出新矩形；确认拖动时框线跟随，松开后左侧 `X1/Y1/X2/Y2` 与矩形同步；返回判定条件后，最终判定应包含同一组 ROI 坐标。再只单击或拖出极小范围，确认上一次有效 ROI 不被覆盖；框选中按 Esc 时应取消本次框选而不是关闭窗口。
9. 使用“下一步”和“上一步”切换，也可点击顶部步骤卡回看；在最后一页检查检测项顺序、必选状态、目标/姿态摘要并点击“确认界面流程”。

预期：下方始终只显示当前步骤，步骤卡正确显示待设置、正在设置或已完成；跳转只切换页面，不补齐任何中间完成状态；步骤只有在必填有效且点击下一步后才变绿，清空已完成步骤的必填项会立即退绿，新增但未选择 ONNX/PT 文件的模型会阻止进入下一步，最终确认会列出尚未完成的步骤。图源单选状态与浅绿视觉状态同步，不出现“USB 已选但文件夹仍绿”或卡片空白区域无法点击；模型库可连续添加多个不同模型，当前模型浅绿高亮，右侧字段与检测项模型下拉框同步；加减和排序操作即时更新有序卡；目标/姿态类型切换不会暴露无关字段；ROI 鼠标框选会按 `640 × 480` 参考坐标实时回填且能恢复误操作前的有效框；最终判定不使用固定示例句，会实时反映目标/姿态设置并拒绝无效数量范围；主操作在 1380 × 860 首屏可见；窗口宽度不足时顶部步骤条可横向滚动；最终显示“界面流程已走完”。整个过程持续显示“不会保存配置”，不会读取真实模型文件或真实图源，也不会修改 `%LocalAppData%\VisualInspectionTestDeployment\projects` 中的项目 JSON。

### AC-MVP-11 登录与角色权限

1. 启动应用，点击“填入管理员”并登录。
2. 确认顶部显示“管理员”和“演示管理员”，并能打开“测试序列设置”和“图源设置”。
3. 关闭并重新启动应用，点击“填入操作员”并登录。
4. 确认顶部显示“操作员”和“演示操作员”，两个设置入口均不可见。
5. 操作员点击“开始测试”，观察执行结果与右侧统计。

预期：两个角色都必须通过账户验证；管理员拥有设置权限；操作员只有执行与统计权限，完整四项测试仍可通过。输入错误密码时登录窗口显示错误且不会进入工作台。

### AC-MVP-12 ONNX 模型标签读取

1. 使用管理员账户进入“测试序列设置 > 模型与标签”。
2. 选择包含标准 ONNX `metadata_props` 标签信息的 `.onnx` 文件。
3. 点击模型路径右侧的“读取标签”。
4. 检查标签列表后点击“应用模型修改”，再执行“校验并保存”。

预期：系统可从 `names`、`labels`、`class_names` 或 `classes` 读取标签，按编号显示为“编号=名称”，并把标签来源切换为“模型导入”；支持 JSON 对象/数组和常见 Python 字典/列表文本。模型没有受支持的元数据、文件损坏或标签格式无效时显示中文错误，原有标签仍可手工编辑；选择 `.pt` 时明确提示当前版本不会执行不安全的 pickle 反序列化。

### AC-MVP-13 空间 ROI 判定与检测框叠加

1. 使用内置通过数据，将“螺钉在位”ROI 设为标准坐标 `145,75,495,285`，参考尺寸 `640 × 360`。
2. 执行测试，观察第一项图像和实测值。
3. 将 ROI 临时缩小到只包含一颗螺钉，再执行测试。
4. 验证后恢复标准 ROI 坐标。

预期：标准 ROI 内四个螺钉框均被计数，图像显示虚线 ROI、检测框、目标名和置信度，第一项通过；缩小 ROI 后只有框中心点位于 ROI 内的螺钉被计数，第一项不通过。检测框低于规则置信度、属于其他 Target 或其他模型绑定时不计入；重叠 ROI 不重复计算同一个框。

### AC-MVP-14 真实 ONNX Detection 推理

1. 在“测试序列设置 > 模型与标签”选择满足静态 `Float[1,3,H,W]` 输入和端到端 `Float[1,N,6]` 输出的 Detection `.onnx`，点击“读取标签”，确认页面显示输入/输出契约。
2. 为要判定的标签创建明确的 Target/Model Binding，并在一个已启用普通测试项中配置对应规则。
3. 在“图源设置”选择含 JPG/JPEG/PNG/BMP 的文件夹；该文件夹可以不含 `detections.json`。
4. 保存后返回工作台，确认模型状态为“真实推理”，点击“开始测试”。

预期：Start 可用；日志显示 `ONNX Runtime CPU`、检测框数量和单次分析毫秒数；图像上的 Detection、Target、Confidence 与规则实测数量一致；模型文件不存在、输入不是 `[1,3,H,W]`、输出不是 `[1,N,6]` 或任务类型不是 Detection 时不进入 Ready。

本次现场模型实测（2026-08-14）：`fan.onnx` 的输入为 `Float[1,3,640,640]`，输出为 `Float[1,300,6]`，包含 6 个标签。在 `IMG_1533.JPG`（5712 × 4284）上检测到 7 个绑定目标：3 个 `Labell`、3 个 `Black_wire`、1 个 `white_wire`；当前开发机 CPU 单帧约 0.55–0.70 秒，整套一项多规则 Runner 判定为 Pass。该结果证明接入链可运行，不等同于正式精度或节拍验收。

### AC-MVP-15 文件夹逐图批量执行与统计

1. 配置一个只包含普通检测项的 Test Sequence，并绑定含多张受支持图片的 Folder 图源。
2. 校验并保存图源后，只点击一次“开始测试”。
3. 观察中部图片、底部日志和右侧统计，直到批量完成。

预期：系统按配置排序读取全部图片；每张图片执行完整普通 Test Sequence，同一图片上的多个普通项共享一次模型分析；日志显示当前文件序号、总数、文件名及逐图结果；Pass/Fail/Error 按已完成图片逐张累计。模型执行错误会保留已完成图片的结果并停止后续批量；损坏文件继续遵守图源的 Skip/Stop 策略；点击“停止”不把未完成图片计入统计。

2026-08-14 使用 `fan.onnx` 和 `Fan\OK` 现场探针验证：一次启动依次处理 `IMG_1533.JPG` 至 `IMG_1547.JPG` 共 15 张，结果为通过 15、不通过 0、错误 0、跳过 0；当前开发机 Debug 探针总耗时约 10 秒。该数值不是正式节拍指标。
