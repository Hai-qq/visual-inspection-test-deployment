# Visual Inspection Test Deployment 验收说明

## 1. 验收结论范围

本说明覆盖三条边界清晰的验收链：v1 兼容路径验收“配置 → Folder → 真实 ONNX Detection 或确定性 Manifest → 规则/姿态 → 工作台/统计/日志”；V2 生产基础验收 schema、配置生命周期、独立 Runner、安全状态机、模拟 Adapter 与 Production fail-closed；8.27 交付链验收“设置端导出 `.sequence.json` + 模型 → 操作端校验导入 → 当前受支持的 v1 ONNX Detection 兼容运行”。三条链不能互相冒充。

仓库的 `v1.0.0` 标签冻结旧版功能基线（应用程序集版本 v0.6.0）。当前 `codex/v2-production-foundation` 严格基于 `780143945700b3b7a18a5056f6a0debd9cf62851`，保留该兼容链并新增正式 V2 基础。现有 Operator 主运行入口尚未切换 V2 Active Pointer；真实 PLC、相机和 Line Adapter 尚未接入。

本版本可以验收：

- 操作工工作台三栏同屏布局与施耐德风格浅色视觉；
- V2 第 02 步的图片/视频文件夹互斥选择与路径前端；旧独立图源窗口仅作 v1 兼容自动验收，不再从操作台进入；
- 管理员测试序列设置的七个配置分区及校验保存；
- ONNX `names`、`labels`、`class_names`、`classes` 标签元数据读取、失败提示和手工修正入口；
- 静态 `Float[1,3,H,W]` 输入、端到端 `Float[1,N,6]` 输出的真实 ONNX Detection CPU 推理；
- Letterbox/RGB/0–1 预处理、原图坐标还原、Class ID 到 Target/Model Binding 显式映射以及模型契约门禁；
- 模型与标签、目标主绑定、普通规则、逻辑关系、阈值和延时编辑；
- 全图/ROI 切换、坐标填写及图像鼠标框选 ROI；
- 姿态步骤画布、步骤参数、新增、删除和顺序调整；
- 中文登录窗口、本地账户验证和管理员/操作员界面隔离；
- PBKDF2-SHA256 密码哈希、错误密码拒绝和禁用账户门禁；
- 测试序列逐项执行、默认/单项延时、开始/停止/复位；
- 纯普通检测项的 Folder Test Sequence 在 Operator 中按“下一张图片 → 以文件名派生序列号 → 一次完整普通序列”执行；同图多个普通项只执行一次模型分析，每张图片只增加一个会话统计结果；Camera 图源在开始时弹窗录入非空序列号并只执行一次检测；
- 普通数量规则、同帧多规则和 AND/OR 引擎；
- Detection 按目标、模型绑定和置信度筛选，Full Image/ROI 按框中心点实际计数；
- ROI 参考尺寸缩放、兼容旧配置的多 ROI 并集去重，以及 ROI/检测框同图叠加；模型原始英文 Output Label 显示在运行图上，Target 中文名留在规则表，置信度继续用于筛选和判定但不绘制；
- 固定线性姿态动作顺序、连续保持和等待超时；
- 当前图片、ROI、标准、实测值、逐项状态和总体结果；
- “当前会话”的通过/不通过/错误、数量/合格率视图；
- 操作工工作台、管理员图源页、示例数据、状态、日志和错误提示均使用简体中文；
- JSON 配置、JSONL 运行日志、冻结九列格式的生产 TXT、Pass/Fail 图片归档和端到端冒烟回执；
- 缺少受支持模型和验收清单时的明确运行门禁。
- schema v2 的 Step Catalog/OrderedInvocations 分层契约、WPF 测试步列表到执行顺序的自动映射、Trigger/Capture/Frame 契约和结构化 Run 状态；
- Draft round-trip、Schema/Runtime 双重校验、不可变 Package、Assignment、Activation 和 Pointer-only Rollback；
- 有界 Trigger 队列、幂等/重复检测、四种 Capture Policy、关联失败/超时/停止/迟到结果不产生 Pass；
- Line Result NotReady/Ready/Busy/ResultLatched/Faulted 与 Ack/断线/旧 Run 隔离；
- V2 WPF 五步 UI：生产型号示例 `FAN-A01`、默认一个“风扇检测”测试步内含 6 个检测标签规则、测试步统一参与总判定、图片/视频文件夹互斥选择、模型删空、ONNX 标签加减与直接编辑、兼容模型选择弹窗、每标签一个默认 ROI 与原比例背景图导入门禁、可选且默认 `0.5` 的置信度、必填标记、可悬停说明 ToolTip，以及“应用到当前操作台 / 独立 `.sequence.json` + 模型导出”；
- Operator sequence 导入、Folder 文件名序列号、Camera 序列号弹窗、单件单图、JSONL/生产结果绑定、运行画面保留原图/模型原始英文 Output Label/检测框且不显示 Target 中文名或置信度、sequence 驱动的检测标签/判定逻辑/本次实测/红绿 Result 表，以及“合格率”命名；
- Acceptance 模拟 Adapter 可执行，Production 在缺少真实全链 Adapter 时保持 NotReady。

本版本不能作为以下项目的验收证据：视频文件夹解码/取帧、自定义 Python/工厂函数执行、工厂序列号格式/重复策略、PT 推理或安全标签提取、动态输入、YOLO Raw/外置 NMS、Classification、Segmentation、Pose/Temporal 真实推理、GPU Provider、通用模型精度、DirectShow、工业相机 SDK、真实 PLC/IO/Line、生产账户增删/改密/外部身份源、原生 V2 Active Pointer 驱动 Operator、历史查询、姿态关键点绘制和正式品牌规范。生产 TXT 与图片落盘只证明本机格式/路径实现，不等于 MES、共享盘或产线归档已经接通。

## 2. 运行条件与入口

- Windows x64；
- .NET 8 Desktop Runtime；
- 发布程序由 C#/.NET 8 WPF 解决方案构建；PowerShell 脚本只编排测试与发布，不属于产品实现；
- 默认 Release：`artifacts\acceptance-zh-CN\VisualInspection.App.exe`。
- 可复制包：`artifacts\VisualInspection-v0.6.0-onnx-yolo-e2e-zh-CN-win-x64.zip`。

前端评审可执行 `powershell -ExecutionPolicy Bypass -File scripts\Build-FrontendDemo.ps1`，生成 `artifacts\frontend-demo-v0.2-YYYYMMDD-win-x64\VisualInspection.FrontendDemo.exe`。该产物是 Windows x64 自包含单文件，默认路径为“登录 → Fan 操作台 → V2 设计界面 → 返回操作台”，不要求安装 .NET 8 Desktop Runtime；EXE 内嵌 `fan.onnx` 和 `IMG_1533.JPG`，操作台与 V2 默认设计都只显示一个“风扇检测”测试步，该步内部包含 6 条 AND 规则。首次管理员登录后模型和图片解包到本机应用数据目录。其真实 ONNX 结果只证明该模型与该图片的接入链可运行，不能替代通用精度、节拍、现场硬件或 V2 Production 验收。

## 3. 人工验收步骤

### AC-MVP-01 启动与同屏布局

1. 启动 `VisualInspection.App.exe`。
2. 使用管理员验收账户登录并确认没有错误弹窗。
3. 查看主窗口。

预期：

- 左侧只显示一个“风扇检测”测试步和带图标的“开始/停止/复位”；该步的标准详情列出 6 条 AND 规则；
- 中部显示 `IMG_1533.JPG`、当前项标准、实测区和结果；
- 右侧“全局统计”始终可见；
- 顶栏图源为“文件夹”且显示“就绪”；
- 状态栏显示真实 ONNX Runtime CPU 已就绪；Folder 图源无需输入序列号即可点击“开始”；
- 底部显示“实时日志”和本机日志路径。

### AC-MVP-02 操作台图源入口唯一性

1. 以管理员登录工作台。
2. 检查右上角设置入口。
3. 打开“测试序列设置”，进入第 02 步“选择图源”。

预期：工作台提供“导入测试序列”和管理员“测试序列设置”，不显示独立“图源设置”；第 02 步提供图片文件夹/视频文件夹互斥选择和文件夹浏览，USB/工业相机为灰态“待开发”。设置窗口右上角显示“返回操作台”；关闭会回到原操作台，导出成功仍停留在设置窗口，“应用到当前操作台”成功后才用当前配置重建操作台。旧 `InputSourceSettingsWindow` 只允许由自动兼容验收直接构造，不作为当前操作台导航。

### AC-MVP-03 完整通过流程

1. 确认当前 Folder 的下一张图片文件名可作为序列号。
2. 点击“开始”，无需在主窗口输入序列号。
3. 观察左侧项目、中部图片与底部日志，等待约 2 秒。

预期：

| 顺序 | 测试步 | 内部规则（AND） | 预期实测 |
| ---: | --- | --- | --- |
| 1 | 风扇检测 | 标签 `= 3`；黑线 `= 3`；白线 `= 1`；反向标签、反向黑线、反向白线均在数量 `> 0` 时 Fail | 同一行显示：`标签=3（通过）; 黑线=3（通过）; 白线=1（通过）; 反向标签=0（通过）; 反向黑线=0（通过）; 反向白线=0（通过）` |

最终结果为“通过”；右侧“有效总数”和“通过”各增加 1，“错误”不变；日志中的序列号等于本张图片的不含扩展名文件名。再次点击开始读取下一张图并再增加一个结果，证明统计对象是每张图片对应的一次完整测试运行，而不是测试项数量。

### AC-MVP-04 不通过场景与数量/合格率统计

1. 完成一次通过运行。
2. 通过隔离验收配置加载内置不通过数据；不得从操作台寻找独立图源设置入口。
3. 点击“开始”执行下一张图片。
4. 在右侧选择“合格率”，再切回“数量”。

预期：“风扇检测”这一行汇总显示标签实测为 2、反向标签实测为 1，并因 6 条 AND 规则中存在失败规则而整体不通过；“当前会话”的有效总数=2、通过=1、不通过=1。数量模式的横向数量条和下方紧凑饼图均显示 1:1 分布；切换到合格率模式后，大型圆环显示 50.0%。错误独立显示，不进入饼图、圆环或合格率分母；无有效结果时饼图显示中性空状态、合格率显示 `--`。隔离验收结束后恢复标准配置。

### AC-MVP-05 Stop 与 Reset

1. 在带有足够测试延时的隔离 Folder 配置中点击“开始”，在单件检测完成前点击“停止”。
2. 点击“复位”。

预期：停止请求取消后，已完成项保留，当前项为“已停止”，未执行项保持“待执行”；本次已停止运行不增加通过/不通过/错误。复位将项目恢复为“待执行”，但不清除已经完成的会话统计。

### AC-MVP-06 模型运行门禁

1. 在当前项目中把所有启用规则所引用的 ONNX 文件临时改为不存在路径或不受支持的输出契约。
2. 使用隔离配置或兼容测试夹具绑定一个存在且含可读图片、但不含 `detections.json` 的文件夹；该步骤不从操作台进入独立图源设置。

预期：首帧预览成功；校验信息同时说明 ONNX 契约不可用且没有 `detections.json`；返回主界面后“开始”禁用，不会使用不存在或结构不匹配的模型产生虚假结果。恢复有效 ONNX 路径，或使用内置通过数据，可恢复 Ready。

### AC-MVP-07 相机适配门禁

1. 在 V2 第 02 步查看 USB 摄像头和工业相机入口。
2. 确认两张卡均为灰态“待开发”，不可选择。

预期：当前前端不显示设备参数、连接或保存控件，不会伪报相机已连接；真实 DirectShow/Vendor 运行门禁继续由隔离自动测试验证。

### AC-MVP-08 运行日志

1. 完成一次 Folder Run。
2. 打开底部显示的 JSONL 路径及同日期生产 TXT，检查对应 Pass/Fail 图片目录。

预期：界面日志显示中文运行消息；JSONL 文件包含运行开始、测试项开始、采集帧、测试项完成和运行完成等结构化事件，并保存相同的 `SerialNumber`、Run ID、图片名和判定。生产 TXT 首行为 `机台|日期|时间|工站|型号|员工号|序列号|测试结果|图片地址|`，数据行保持九列且末尾带 `|`。结果图片进入 `images\pass` 或 `images\fail`，文件名由安全化序列号、毫秒时间和 `PASS`/`FAIL` 组成，TXT 图片地址指向实际文件。

### AC-MVP-09 管理员测试序列设置

本项仅适用于 `v1.0.0` 标签或既有 v0.6.0 正式验收包。当前分支的管理员主入口打开现役五步设置向导；经典设置步骤只用于兼容基线，不能代替下方新交互验收。

1. 在管理员登录后的工作台顶部点击“测试序列设置”。
2. 依次查看“常规、模型与标签、目标与绑定、规则与 ROI、姿态序列、输入源、用户与权限”。
3. 在“常规”中修改默认延时，点击“校验并保存”，再重新打开窗口核对。

预期：七个分区均可显示；配置保存后主工作台自动重载；再次打开时默认延时为保存后的值。完成验收后可恢复为 100 毫秒。

### AC-MVP-10 规则、ROI 与姿态画布

1. 在“规则与 ROI”中选择“螺钉在位”，确认目标、模型绑定、在场数量、等于 4、条件成立时通过等字段已回填。
2. 点击“新增检测项”，确认列表选中新建的“普通检测项 1”，并已自动填入一条全图、在场数量等于 1、成立时通过的默认规则；点击“删除检测项”恢复原序列。Classification 绑定应改用“是否存在等于 1”的默认规则。
3. 将“螺钉在位”的区域切换为 ROI，在预览图上拖动框选，确认 X1/Y1/X2/Y2 随鼠标更新；点击“应用规则”。
4. 在“姿态序列”中查看“拿取 → 放置 → 确认”动作画布；选择步骤后检查动作条件、模型绑定、保持时间和最大等待时间。
5. 如测试上移/下移，执行相反操作恢复原顺序后再保存。

预期：新增普通检测项立即具有可编辑、可校验的默认规则；删除后剩余测试项顺序连续，且不能删除序列中的最后一个测试项。ROI 坐标与画布一致且通过配置边界校验；姿态画布按步骤顺序更新；保存后操作员工作台显示最新标准，完整内置通过流程仍可正常执行。

### AC-V2-UI-01 Test Sequence Setting 五步设置、应用与导出

1. 执行 `dotnet run --project src\VisualInspection.App\VisualInspection.App.csproj -- --v2-wizard-preview`，或以管理员从工作台进入 V2。
2. 确认五个顶层步骤整体居中；直接跳步不补绿，必填内容失效会退绿。
3. 在“选择图源”中先选择图片文件夹并填写路径，再选择视频文件夹。确认图片立即取消选中，下方仍为文件夹浏览面板，但标题和说明切换为视频，并可填写独立的视频文件夹路径；往返切换后两类路径各自保留。确认 USB 摄像头和工业相机均显示灰态“待开发”、无法选择，也不出现任何相机参数面板。
4. 在模型页确认模型列表顶部并排显示“添加模型 / 删除当前”；逐个删除并确认允许删到空，引用该模型的未交付测试步同步清理且不留下悬空引用。重新添加 ONNX 模型并选择文件，确认自动尝试读取标签；使用加号添加、直接编辑名称、减号删除标签，界面不出现“自动识别/手动填写”下拉框。任务类型只包含目标检测、姿态/时序和图像分割。
5. 确认型号默认显示生产代码 `FAN-A01`，不再显示“Fan 完整性检测”；测试步基本信息的检测类型包含“目标检测（单张图）/姿态动作（连续帧）/图像分割（单张图）”，且不出现“是否必选 / 设为必选项”。点击新增测试步或“选择模型”后应打开独立弹窗，且只列出当前类型兼容模型；选择后才更新绑定并进入检测标签列表。没有模型时应引导返回第 03 步。切换测试步后，模型、类型和检测标签跟随当前项；改绑模型时旧模型的不兼容标签被移除。
