# Visual Inspection Test Deployment 验收说明

## 1. 验收结论范围

本说明同时覆盖两条边界清晰的验收链：v1 兼容路径验收“配置 → Folder → 真实 ONNX Detection 或确定性 Manifest → 规则/姿态 → 工作台/统计/日志”；V2 生产基础验收 schema、配置生命周期、独立 Runner、安全状态机、模拟 Adapter、Production fail-closed 与 WPF Draft 映射。两条链不能互相冒充。

仓库的 `v1.0.0` 标签冻结旧版功能基线（应用程序集版本 v0.6.0）。当前 `codex/v2-production-foundation` 严格基于 `780143945700b3b7a18a5056f6a0debd9cf62851`，保留该兼容链并新增正式 V2 基础。现有 Operator 主运行入口尚未切换 V2 Active Pointer；真实 PLC、相机和 Line Adapter 尚未接入。

本版本可以验收：

- 操作工工作台三栏同屏布局与施耐德风格浅色视觉；
- V2 第 02 步的图片/视频文件夹互斥选择与路径前端；旧独立图源窗口仅作 v1 兼容自动验收，不再从操作台进入；
- 管理员测试序列设置的七个配置分区及校验保存；
- ONNX `names`、`labels`、`class_names`、`classes` 标签元数据读取、失败提示和手工修正入口；
- 静态 `Float[1,3,H,W]` 输入、端到端 `Float[1,N,6]` 输出的真实 ONNX Detection CPU 推理；
- Letterbox/RGB/0–1 预处理、原图坐标还原、Class ID 到 Target/Model Binding 显式映射以及模型契约门禁；
- 模型与标签、目标主绑定、普通规则、逻辑关系、阈值和延时编辑；
- 全图/ROI 切换、坐标填写及图像鼠标框选 ROI；
- 姿态步骤画布、步骤参数、新增、删除和顺序调整；
- 中文登录窗口、本地账户验证和管理员/操作员界面隔离；
- PBKDF2-SHA256 密码哈希、错误密码拒绝和禁用账户门禁；
- 测试序列逐项执行、默认/单项延时、开始/停止/复位；
- 纯普通检测项的 Folder Test Sequence 在 Operator 中按“一个非空序列号 → 下一张图片 → 一次完整普通序列”执行；同图多个普通项只执行一次模型分析，一个序列号只增加一个会话统计结果；
- 普通数量规则、同帧多规则和 AND/OR 引擎；
- Detection 按目标、模型绑定和置信度筛选，Full Image/ROI 按框中心点实际计数；
- ROI 参考尺寸缩放、多 ROI 并集去重，以及 ROI/检测框同图叠加；模型输出目标名和置信度仍用于判定与详情，但不再绘制到运行图像上；
- 固定线性姿态动作顺序、连续保持和等待超时；
- 当前图片、ROI、标准、实测值、逐项状态和总体结果；
- “当前会话”的通过/不通过/错误、数量/合格率视图；
- 操作工工作台、管理员图源页、示例数据、状态、日志和错误提示均使用简体中文；
- JSON 配置、JSONL 运行日志和端到端冒烟回执；
- 缺少受支持模型和验收清单时的明确运行门禁。
- schema v2 的 Step Catalog/OrderedInvocations 分层契约、WPF 测试步列表到执行顺序的自动映射、Trigger/Capture/Frame 契约和结构化 Run 状态；
- Draft round-trip、Schema/Runtime 双重校验、不可变 Package、Assignment、Activation 和 Pointer-only Rollback；
- 有界 Trigger 队列、幂等/重复检测、四种 Capture Policy、关联失败/超时/停止/迟到结果不产生 Pass；
- Line Result NotReady/Ready/Busy/ResultLatched/Faulted 与 Ack/断线/旧 Run 隔离；
- V2 WPF 五步 UI 当前只验收前端内容：图片/视频文件夹互斥选择与独立路径保持、USB/工业相机灰态待开发、模型分类移除与标签来源下拉、测试步的目标检测/姿态动作/图像分割三类选择、按检测类型过滤模型及自动联动、Model 后自动打开的 Label 列表、单 Label 独立区域/判定弹窗、多 Label 追加与定向重编辑、多命名 ROI 及实时区域摘要、固定相机提示、姿态模型触发的动作顺序弹层、基本信息摘要/重新编辑入口、自定义函数页内切换测试步、精简最终页，以及底栏仅保留上一步/下一步；
- Operator 非空产品序列号门禁、录入后仍需点击开始、单序列号单件单图、基础 JSONL 序列号结果绑定、运行画面隐藏模型标签/置信度文字，以及“合格率”命名；
- Acceptance 模拟 Adapter 可执行，Production 在缺少真实全链 Adapter 时保持 NotReady。

本版本不能作为以下项目的验收证据：视频文件夹解码/取帧、检测弹窗新增状态到正式 V2 Draft/RuleSet/Region 的完整映射、自定义 Python/工厂函数执行、工厂序列号格式/重复策略/最终日志格式及完整图片留存追溯、PT 推理或安全标签提取、动态输入、YOLO Raw/外置 NMS、Classification、Segmentation、Pose/Temporal 真实推理、GPU Provider、通用模型精度、DirectShow、工业相机 SDK、真实 PLC/IO/Line、生产账户增删/改密/外部身份源、V2 Operator 现场切换、历史查询、姿态关键点绘制和正式品牌规范。当前仅验证非空序列号、单件单图以及基础 JSONL 字段绑定。V2 发布/回滚当前是本机不可变配置生命周期，不等于真实工位已经启用。

## 2. 运行条件与入口

- Windows x64；
- .NET 8 Desktop Runtime；
- 发布程序由 C#/.NET 8 WPF 解决方案构建；PowerShell 脚本只编排测试与发布，不属于产品实现；
- 默认 Release：`artifacts\acceptance-zh-CN\VisualInspection.App.exe`。
- 可复制包：`artifacts\VisualInspection-v0.6.0-onnx-yolo-e2e-zh-CN-win-x64.zip`。

前端评审可执行 `powershell -ExecutionPolicy Bypass -File scripts\Build-FrontendDemo.ps1`，生成 `artifacts\frontend-demo-v0.2-YYYYMMDD-win-x64\VisualInspection.FrontendDemo.exe`。该产物是 Windows x64 自包含单文件，双击后直接进入 V2 前端确认稿，不要求安装 .NET 8 Desktop Runtime；它不能替代本节默认 Release 的登录、Runner 或生产能力验收。

本地验收账户：

| 角色 | 用户名 | 密码 | 预期入口 |
| --- | --- | --- | --- |
| 管理员 | `admin` | `Admin@123` | 测试执行、统计、测试序列设置（含第 02 步图源） |
| 操作员 | `operator` | `Operator@123` | 仅测试执行与统计 |

固定密码只用于本地验收。账户文件位于 `%LocalAppData%\VisualInspectionTestDeployment\users\users.json`，其中不保存明文密码。

首次启动会创建：

```text
%LocalAppData%\VisualInspectionTestDeployment\projects\00000000000000000000000000000001.json
%LocalAppData%\VisualInspectionTestDeployment\acceptance-data\sample-set-01\
%LocalAppData%\VisualInspectionTestDeployment\acceptance-data\sample-set-fail\
```

每组内置数据含 12 张 640 × 360 BMP。第 1–3 张分别用于螺钉、标签和表面瑕疵项；第 4–12 张以每 3 帧一个动作的方式模拟拿取、放置、确认。默认 `sample-set-01` 为全通过；`sample-set-fail` 在第 3 帧提供一个表面瑕疵，使第三项和整体运行不通过。

## 3. 人工验收步骤

### AC-MVP-01 启动与同屏布局

1. 启动 `VisualInspection.App.exe`。
2. 使用管理员验收账户登录并确认没有错误弹窗。
3. 查看主窗口。

预期：

- 左侧为 4 项测试序列和带图标的“开始/停止/复位”；
- 中部显示内置首帧、当前项标准、实测区和结果；
- 右侧“全局统计”始终可见；
- 顶栏图源为“文件夹”且显示“就绪”；
- 状态栏显示验收清单适配器已就绪；未输入序列号时“开始”禁用，输入非空验收序列号后可点击；
- 底部显示“实时日志”和本机日志路径。

### AC-MVP-02 操作台图源入口唯一性

1. 以管理员登录工作台。
2. 检查右上角设置入口。
3. 打开“测试序列设置 V2”，进入第 02 步“选择图源”。

预期：工作台只显示“测试序列设置 V2”，不显示独立“图源设置”；第 02 步提供图片文件夹/视频文件夹互斥选择和文件夹浏览，USB/工业相机为灰态“待开发”。旧 `InputSourceSettingsWindow` 只允许由自动兼容验收直接构造，不作为当前操作台导航。

### AC-MVP-03 完整通过流程

1. 在主窗口输入非空验收序列号，例如 `SN-PASS-001`。
2. 点击“开始”。
3. 观察左侧项目、中部图片与底部日志，等待约 2 秒。

预期：

| 顺序 | 项目 | 标准 | 预期实测 |
| ---: | --- | --- | --- |
| 1 | 螺钉在位 | ROI 中数量 `= 4` | `螺钉=4`，通过 |
| 2 | 标签对齐 | 全图数量 `= 1` | `标签=1`，通过 |
| 3 | 表面瑕疵 | 数量 `> 0` 时不通过 | `表面瑕疵=0`，通过 |
| 4 | 动作序列 | 拿取 → 放置 → 确认 | 三步依次确认，通过 |

最终结果为“通过”；右侧“有效总数”和“通过”各增加 1，“错误”不变；输入框清空。再次执行必须先录入新的序列号，完成后两项各再增加 1，证明统计对象是一个序列号对应的完整测试运行，而不是测试项或文件夹图片总数。

### AC-MVP-04 不通过场景与数量/合格率统计

1. 完成一次通过运行。
2. 通过隔离验收配置加载内置不通过数据；不得从操作台寻找独立图源设置入口。
3. 输入新的序列号，再执行一次测试运行。
4. 在右侧选择“合格率”，再切回“数量”。

预期：第三项“表面瑕疵”实测为 1 并不通过，整体不通过；“当前会话”的有效总数=2、通过=1、不通过=1。数量模式的横向数量条和下方紧凑饼图均显示 1:1 分布；切换到合格率模式后，大型圆环显示 50.0%。错误独立显示，不进入饼图、圆环或合格率分母；无有效结果时饼图显示中性空状态、合格率显示 `--`。隔离验收结束后恢复标准配置。

### AC-MVP-05 Stop 与 Reset

1. 输入序列号并点击“开始”，在姿态图片播放阶段点击“停止”。
2. 点击“复位”。

预期：停止请求取消后，已完成项保留，当前项为“已停止”，未执行项保持“待执行”；本次已停止运行不增加通过/不通过/错误。复位将项目恢复为“待执行”，但不清除已经完成的会话统计。

### AC-MVP-06 模型运行门禁

1. 在当前项目中把所有启用规则所引用的 ONNX 文件临时改为不存在路径或不受支持的输出契约。
2. 使用隔离配置或兼容测试夹具绑定一个存在且含可读图片、但不含 `detections.json` 的文件夹；该步骤不从操作台进入独立图源设置。

预期：首帧预览成功；校验信息同时说明 ONNX 契约不可用且没有 `detections.json`；返回主界面后“开始”禁用，不会使用不存在或结构不匹配的模型产生虚假结果。恢复有效 ONNX 路径，或使用内置通过数据，可恢复 Ready。

### AC-MVP-07 相机适配门禁

1. 在 V2 第 02 步查看 USB 摄像头和工业相机入口。
2. 确认两张卡均为灰态“待开发”，不可选择。

预期：当前前端不显示设备参数、连接或保存控件，不会伪报相机已连接；真实 DirectShow/Vendor 运行门禁继续由隔离自动测试验证。

### AC-MVP-08 运行日志

1. 输入序列号并完成一次 Run。
2. 打开底部显示的 JSONL 路径。

预期：界面日志显示中文运行消息；JSONL 文件包含运行开始、测试项开始、采集帧、测试项完成和运行完成等结构化事件，并在本次图片结果中保存相同的 `SerialNumber`、Run ID、图片名和判定。业务不通过与系统错误使用不同的判定值和级别。

### AC-MVP-09 管理员测试序列设置

本项仅适用于 `v1.0.0` 标签或既有 v0.6.0 正式验收包。当前分支的管理员主入口打开 V2 前端确认稿；经典设置步骤只用于兼容基线，不能代替下方新前端交互验收。

1. 在管理员登录后的工作台顶部点击“测试序列设置”。
2. 依次查看“常规、模型与标签、目标与绑定、规则与 ROI、姿态序列、输入源、用户与权限”。
3. 在“常规”中修改默认延时，点击“校验并保存”，再重新打开窗口核对。

预期：七个分区均可显示；配置保存后主工作台自动重载；再次打开时默认延时为保存后的值。完成验收后可恢复为 100 毫秒。

### AC-MVP-10 规则、ROI 与姿态画布

1. 在“规则与 ROI”中选择“螺钉在位”，确认目标、模型绑定、在场数量、等于 4、条件成立时通过等字段已回填。
2. 点击“新增检测项”，确认列表选中新建的“普通检测项 1”，并已自动填入一条全图、在场数量等于 1、成立时通过的默认规则；点击“删除检测项”恢复原序列。Classification 绑定应改用“是否存在等于 1”的默认规则。
3. 将“螺钉在位”的区域切换为 ROI，在预览图上拖动框选，确认 X1/Y1/X2/Y2 随鼠标更新；点击“应用规则”。
4. 在“姿态序列”中查看“拿取 → 放置 → 确认”动作画布；选择步骤后检查动作条件、模型绑定、保持时间和最大等待时间。
5. 如测试上移/下移，执行相反操作恢复原顺序后再保存。

预期：新增普通检测项立即具有可编辑、可校验的默认规则；删除后剩余测试项顺序连续，且不能删除序列中的最后一个测试项。ROI 坐标与画布一致且通过配置边界校验；姿态画布按步骤顺序更新；保存后操作员工作台显示最新标准，完整内置通过流程仍可正常执行。

### AC-V2-UI-01 Test Sequence Setting V2 前端确认稿

1. 执行 `dotnet run --project src\VisualInspection.App\VisualInspection.App.csproj -- --v2-wizard-preview`，或以管理员从工作台进入 V2。
2. 确认五个顶层步骤整体居中；直接跳步不补绿，必填内容失效会退绿。
3. 在“选择图源”中先选择图片文件夹并填写路径，再选择视频文件夹。确认图片立即取消选中，下方仍为文件夹浏览面板，但标题和说明切换为视频，并可填写独立的视频文件夹路径；往返切换后两类路径各自保留。确认 USB 摄像头和工业相机均显示灰态“待开发”、无法选择，也不出现任何相机参数面板。
4. 在模型页确认模型列表顶部并排显示“添加模型 / 删除当前”；连续添加模型后选中其中一个并删除，确认只删除当前模型。尝试删除已被测试步引用的模型或最后一个模型时应被阻止。随后确认任务类型只包含目标检测、姿态/时序和图像分割，不出现图像分类；把标签来源从自动识别切换为手动填写，确认精简编辑区按需展开。
5. 确认测试步基本信息的检测类型包含“目标检测（单张图）/姿态动作（连续帧）/图像分割（单张图）”。依次切换三种类型，确认模型下拉框只显示当前类型的模型；有同类模型时自动改绑，没有时显示返回第 03 步的提示。只展开再关闭模型下拉框且不改选时，当前模型不得变空，也不得打开 Label 弹窗。建立或选择两个分别绑定不同模型的单帧测试步，在二者之间切换，确认基本信息里的模型、类型和检测子项分别跟随当前测试步。将其中一个模型设为图像分割并在测试步绑定，确认类型自动切换为“图像分割”，仍自动打开逐 Label 列表并可进入整图/ROI 与判定弹窗。改绑模型后旧模型的不兼容检测子项应被移除，Label 列表按新模型重建；弹窗只读显示当前模型，不再提供第二个模型下拉框。
6. 将当前 Label 设为 ROI，同时勾选 ROI-01、ROI-02，并设置该 Label 的判定条件；确认右侧判定区立即显示两个区域名称，区域区显示“仅适用于固定摄像头”。拖拽 ROI 后坐标更新，Esc/小框保护仍有效。保存后应返回 Label 列表，再配置第二个 Label 为整图和另一组判定；基本信息页显示两个检测子项摘要。
7. 重新编辑第一个 Label 并保存，确认只更新第一个子项，第二个 Label 的区域和判定保持不变；删除任一子项时也不得清空其余 Label。
8. 将普通测试步的检测类型改为姿态，或选择已有姿态测试步，确认模型下拉框只显示姿态模型且页签仍只有“基本信息、自定义函数”。首次选定姿态模型后动作顺序弹层应自动出现；检查连续编号、排序及每个动作独立的 Model、Label、Hold、Wait。保存后应回到基本信息并显示顺序摘要与“重新编辑动作顺序”，取消或按 Esc 应恢复弹层打开前的动作内容。
9. 进入自定义函数页，通过页首“当前测试步”下拉框在至少两个测试步之间直接切换，分别配置函数名称、Python 文件和延时并确认互不覆盖；界面不得出现旧“触发与运行”演示参数，也不得声称会执行 Python。
10. 在测试步页确认不再出现“Sequence Plan · 有序调用编排”；左侧测试步列表明确标注“从上到下执行”，可新增、删除及上下移动。移动后最终页顺序同步变化；内部 FunctionCode 和 InvocationId 不在前端显示。
11. 进入最终页，确认图源、模型、检测子项、姿态动作、自定义函数、测试步从上到下执行顺序、序列号/启动方式和运行显示约定随当前前端状态更新；页面不得显示 Deployment、Lifecycle、Schema/Runtime 或 Publish 状态。

### AC-MVP-14 真实 ONNX Detection 推理

1. 在“测试序列设置 > 模型与标签”选择满足静态 `Float[1,3,H,W]` 输入和端到端 `Float[1,N,6]` 输出的 Detection `.onnx`，点击“读取标签”，确认页面显示输入/输出契约。
2. 为要判定的标签创建明确的 Target/Model Binding，并在一个已启用普通测试项中配置对应规则。
3. 通过测试序列配置或隔离项目配置绑定含 JPG/JPEG/PNG/BMP 的文件夹；该文件夹可以不含 `detections.json`，操作台不提供独立图源设置入口。
4. 返回工作台，确认模型状态为“真实推理”，输入序列号并点击“开始”。

预期：“开始”可用；日志显示 `ONNX Runtime CPU`、检测框数量和单次分析毫秒数；图像上的 Detection、Target、Confidence 与规则实测数量一致；模型文件不存在、输入不是 `[1,3,H,W]`、输出不是 `[1,N,6]` 或任务类型不是 Detection 时不进入 Ready。

本次现场模型实测（2026-08-14）：`fan.onnx` 的输入为 `Float[1,3,640,640]`，输出为 `Float[1,300,6]`，包含 6 个标签。在 `IMG_1533.JPG`（5712 × 4284）上检测到 7 个绑定目标：3 个 `Labell`、3 个 `Black_wire`、1 个 `white_wire`；当前开发机 CPU 单帧约 0.55–0.70 秒，整套一项多规则 Runner 判定为 Pass。该结果证明接入链可运行，不等同于正式精度或节拍验收。

### AC-MVP-15 文件夹单序列号单图执行与统计

1. 配置一个只包含普通检测项的 Test Sequence，并绑定至少包含两张受支持图片的 Folder 图源。

预期：第一次只读取排序后的第一张图片，第二次只读取下一张图片；每张图片执行完整普通 Test Sequence，同一图片上的多个普通项共享一次模型分析。每次运行只增加一个 Pass/Fail/Error，不能由一个序列号一次产生 15 个结果。JSONL 的 `serial-image-completed` 事件分别保存 `SN-IMAGE-001` / `SN-IMAGE-002`、对应图片名、Run ID 和判定。损坏文件继续遵守图源的 Skip/Stop 策略；同一应用会话到达文件夹末尾后从第一张重新开始。

2026-08-14 的 15 张 `fan.onnx` 文件夹批量探针只保留为底层离线批量执行证据，不再代表 Operator 的启动语义或统计口径。
