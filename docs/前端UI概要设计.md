# Visual Inspection Test Deployment 前端 UI 概要设计

应用与导出页简化：顶部列出基础检查结果及未完成/未确认项，每项提供“返回修改”；中间一行显示型号、图源、模型数与测试步数。项目、模型名称、执行顺序和函数详情放入默认折叠的“查看详细配置”。函数提示仅在存在函数名称时显示，并明确暂不执行。序列号、运行图与记录方式放入“运行与记录说明”按钮的帮助提示，支持悬停或点击打开，内容自动换行；Esc 优先关闭提示。实际导出期间禁用编辑、导航、重复导出、应用及窗口关闭，完成或失败后恢复；失败会清除上一次成功提示。底栏保留上一步、次操作“导出 Sequence 与模型”和主操作“应用到当前操作台”；原有确认、导出和应用校验保持。

2026-09-07 启动规则更新：正常登录及操作台预览每次均显示“未加载测试序列”，测试步为 0、图像与规则为空、统计为 0；开始/停止/复位禁用，中央与顶栏提供导入入口。导入取消或失败保留当前状态；导入处理中暂禁重复导入、开始及设置，结束后恢复。管理员从空操作台打开设置时，项目/型号/路径/模型/测试步为空，支持自行建立配置并应用。磁盘旧配置保留但不自动恢复。下面 Fan 内容仅指显式验收/向导预览夹具或已导入的代表配置，不是默认操作台。

## 1. 设计结论

2026-09-07 整体复查调整：操作台未导入时显示浅色网格，不预载内置风扇示意图；已导入或已应用的图源仍显示真实预览内容。左右辅助栏为 210/240 px，数量/合格率图随可用高度缩放，最小窗口下不再裁切。设置页步骤区按内容自动定高、最小 88 px，内容标题区为 54 px；模型列表和测试步列表均宽 268 px，编辑区随窗口宽度伸缩。测试步名称和类型并排、绑定模型独占一行；检测标签区独立滚动，默认 1380 × 860 窗口完整显示六条规则。表单正文为 13 px，辅助文字至少 12 px，按钮模板实际应用 Padding。模型页六个常用英文标签在最小窗口完整显示；自定义函数页将当前测试步选择合入表单标题区，移除重复卡片，默认字段在最小窗口无需滚动。

标签编辑弹窗根据检测区域调整：整张图使用紧凑的两列表单；ROI 使用左侧可伸缩画布和右侧判定表单。弹窗宽度受窗口约束，保存按钮位于独立底栏，置信度输入框宽 160 px。已复核 1120 × 720 最小窗口：弹窗、画布、重新框选和保存按钮完整可见，规则列表可滚动至最后一条。顶部 64 px 步骤卡片居中，导航容器上下留白并按内容自动定高，启用像素对齐，完整显示五张卡片的下边框。姿态动作弹窗覆盖整个窗口，参数区独立滚动；打开时恢复有效的当前动作，缺失选择时选中第一项，避免参数空白。截图及布局断言见根目录 `design-qa.md` Pass 21–23。

2026-09-07 配置回读修复：设置页从既有配置恢复全部标签及实际规则摘要；各标签独立保存 Full Image/ROI。缺失数量增加“应有总数”，判定面板允许滚动，保存按钮保持在固定底栏。自定义函数页面明确提示只保存配置、不调用函数。操作台图像角标显示实际尺寸和运行类型；状态栏分列省略长文本并提供完整 ToolTip；标签避让后绘制在检测框上层。验证记录见项目根目录 `design-qa.md` Pass 18。

Operator 主界面采用**图像为主体、两侧辅助、底部紧凑明细**的结构。测试执行与全局统计始终在同一页面同时可见：

- 左侧回答“执行到哪一步、每一步是什么状态”；
- 中部回答“当前看到了什么、按什么标准判断、实测结果是什么”；
- 右侧回答“当前运行或当前会话总体检测情况如何”；
- 顶部持续显示 Project、Test Sequence 和当前图源；
- 底部保留运行状态，实时日志默认折叠；完整历史查询后续进入独立页面。

本设计不使用游戏化视觉，不使用深色仪表盘，不把统计拆为独立页面，也不在不同区域重复堆放同一批测试信息。

## 2. 设计目标

1. 操作工在一个页面内完成图源确认、启动测试、观察当前项和查看统计。
2. 当前测试项、总体结果和系统异常具有明确且互不混淆的视觉层级。
3. 浅色、淡雅、克制，同时保留施耐德软件测试工具的工业感和绿色识别色。
4. 高信息密度但不拥挤，避免完整表格、图表和日志同时争夺注意力。
5. Admin 配置能力与 Operator 执行能力分离，避免操作工误改检测标准。

## 3. 页面信息架构

### 3.1 页面区域

| 区域 | 基准尺寸 | 是否固定 | 主要职责 |
| --- | ---: | :---: | --- |
| 顶部应用栏 | 高 68 px | 是 | Project、Test Sequence、图源、用户和时间 |
| 左侧 Test Sequence | 宽 210 px | 是 | 全序列进度、测试项状态和执行控制 |
| 中部检测工作区 | 剩余宽度，建议不小于 680 px | 否 | 图像、ROI 和检测叠加 |
| 右侧全局统计 | 宽 240 px | 是 | 数量、合格率、图表和辅助统计 |
| 底部状态与日志 | 状态条高 36 px，日志展开增加 140 px | 否 | 最新运行状态、按需展开的日志和文件路径 |

1440 px 宽度下，左右固定栏合计 450 px，其余宽度优先留给中部图像。窗口缩放时，中部区域先自适应；右侧统计不得隐藏，左侧项目名称可省略显示但状态图标必须保留。

### 3.2 信息唯一归属

| 信息 | 唯一主展示区域 | 其他区域允许展示的摘要 |
| --- | --- | --- |
| Test Sequence 全部测试项 | 左侧 | 中部只显示当前项 |
| 当前项标准和实测值 | 中部 | 左侧只显示状态 |
| Pass/Fail 汇总数量和合格率 | 右侧 | 中部只显示当前项结果 |
| 当前图源和连接状态 | 顶部 | 图像工具条可显示采集参数 |
| 紧凑实时日志 | 底部状态区 | 内部 JSONL 与生产 TXT/图片保存在本机文件 |

禁止在左侧列表、中部详情和底部日志中同时显示三份完整测试结果表。

## 4. 顶部应用栏

### 4.1 内容顺序

从左到右依次为：

1. 产品名称 `Visual Inspection Test Deployment`；
2. 当前 Project；
3. 当前 Test Sequence 和 Version；
4. 当前图源；
5. 图源连接状态；
6. 当前用户；
7. 当前日期和时间。

### 4.2 图源显示与切换

顶部图源控件使用统一格式：

- Camera：`Camera 01 · Live`；
- Folder：`Folder · Production Images`；
- 正常：绿色圆点和文字 `Ready`/`Live`；
- 等待或警告：黄色图标和可读说明；
- 断开或不可用：红色图标和可操作错误说明。

权限行为：

- 默认采用 Fixed Source，图源控件只读；
- Admin 启用 Runtime Source Switching 后，控件变为下拉选择；
- Operator 只能选择 Admin 已配置、已验证且授权给当前 Test Sequence 的图源；
- 图源只能在测试开始前切换；Running 状态下控件禁用；
- 相机参数、文件夹路径和遍历规则不得在 Operator 页面修改。

## 5. 左侧 Test Sequence 区

### 5.1 顶部摘要

显示：

- Test Sequence 名称；
- 当前进度，例如 `Step 2 of 4`；
- 一条细进度条；
- 当前运行状态，例如 Ready、Running、Stopped、Completed。

### 5.2 测试项列表

每行高度建议为 56–64 px，只显示：

- 顺序编号；
- 测试项名称；
- 状态图标与状态文字。

状态包括：

| 状态 | 展示方式 |
| --- | --- |
| Pending | 灰色空心圆 + `Pending` |
| Running | 绿色进度指示 + `Running`，使用浅绿色行底 |
| Pass | 勾选图标 + `Pass` |
| Fail | 叉号图标 + `Fail` |
| Error | 警告图标 + `Error` |
| Stopped | 停止图标 + `Stopped` |

列表不显示模型、完整标准、坐标和详细实测值，避免与中部当前项详情重复。

### 5.3 执行控制

主界面不常驻显示序列号输入框。Folder 图源点击 `开始` 后直接取排序后的下一张图片，并以不含扩展名的图片文件名作为该件产品序列号；文件名为空或无法形成有效序列号时失败关闭。Camera 图源点击 `开始` 后先弹出序列号输入框，只有提交非空值才执行一次检测，取消弹窗则不采集、不计数。当前只做非空门禁，不把任意非空文本声明为已通过工厂格式或重复策略校验。

左侧底部固定放置三枚“图标 + 短文”执行按钮，按钮使用清晰边框和轻微按压层次模拟工位实体按钮，同时保留文字以避免只靠图标猜测：

- `开始`：播放图标，唯一高强调绿色主按钮；
- `停止`：停止图标，Running 时可用；
- `复位`：回转图标，Running 时禁用。

按钮位置在不同 Test Sequence 长度下保持不变。

Folder 图源且全部启用项均为普通检测项时，`开始` 代表一次单件任务：只读取排序后的下一张图片，并让该图片执行完整普通 Test Sequence；同一图片的多个普通项共享一次分析。底部状态/日志显示 `序列号 · 文件名 · 结果`，统计只增加一个结果。再次点击开始读取下一张图片；同一应用会话到达文件夹末尾后从第一张重新开始。含姿态项时一个序列号仍对应一个产品，但可按动作判定需要读取连续帧。

## 6. 中部检测工作区

### 6.1 图像工具条

只保留与当前观察直接相关的控件：

- Show Overlays；
- Fit / 100%；
- 当前分辨率；
- 当前 FPS；
- 当前采集状态。

不得在工具条加入模型管理、相机高级参数或统计设置。

### 6.2 图像画布

图像画布占中部主要空间，显示：

- 实时相机帧或当前文件夹图片；
- Detection Bounding Box；
- ROI；
- Pose Keypoints 或当前动作提示；
- 必要的缩放、适应窗口和隐藏叠加层功能。

叠加层要求：

- Detection 使用醒目的实线框，ROI 使用不同颜色的虚线框与区域名称；两者不能只靠颜色区分；
- 运行画面保留原始图片、ONNX 模型的原始英文 Output Label 和检测框，标签与检测框使用同一颜色；不得把框上文字替换为 Target 中文显示名，图上不显示置信度，文字背景保持紧凑，不能覆盖大面积产品区域；
- 检测框和 ROI 线宽按原图相对 `640 × 360` 参考画布的比例缩放，保证 5712 × 4284 等高分辨率原图缩入窗口后仍清楚可读；
- 当前实现基准值为 Detection 线宽 4 px、ROI 线宽 4 px；ROI 区域名称可保留用于区分配置区域；
- Fail 目标可以使用红色框，但不得使整个画面大面积变红；
- Error 不作为检测框结果显示，应在状态区域解释原因。

当前分支沿用 v0.6.0 的真实 Folder 帧，并按原始像素比例合成当前规则 ROI 与真实 ONNX 或验收清单 Detection Bounding Box；同一空间框同时用于规则计数，避免显示与判定分叉。运行图像通过 Model Binding 的 `OutputLabelId` 回查模型 LabelSet，并显示其原始英文名称；Target 中文名继续用于规则表和业务判定。Confidence 继续用于检测筛选、规则和结构化记录，但不显示在检测完成后的图片上。Pose Keypoints 和 Overlays 开关仍未实现，当前不伪造。

### 6.3 当前测试项详情

图像下方设置全宽 174 px 当前项详情区。规则明细按两列排布，默认六条规则占三行；更多规则可滚动。当前项名称下显示该项使用“全部满足（AND）”还是“任一满足（OR）”；标签规则用最简表格呈现：

| 检测标签 | 判定逻辑 | 本次实测 | Result |
| --- | --- | --- | --- |
| fan | 数量 = 1 → 通过 | 1 个 | PASS（绿色） |
| reverse_fan | 数量 > 0 → 不通过 | 0 个 | PASS（绿色） |
| safety_label | 存在 → 通过 | 存在 · 1 个 | PASS（绿色） |

表格行来自当前 Test Sequence 的全部标签规则，而不是只列本次检测到的目标。运行前先显示配置的在场数量、缺失数量、存在/不存在、等于/不等于、大小比较或闭区间逻辑，实测与 Result 显示“待检测 / —”；运行后同名 Detection 按标签与 ROI 计数，并根据规则指标显示数量、缺失数量或存在状态。每行 `Result` 根据该规则显示绿色 PASS、红色 FAIL 或 Error 警示色；此表不扩展为整个 Test Sequence 历史表。

## 7. 右侧全局统计区

右侧统计栏与图像区同高；空间不足时内部滚动，优先保留图像和规则明细。

### 7.1 统计范围

当前实现固定显示当前会话统计。

定义：

- Current Run：当前序列号对应产品的一次 Test Sequence 结果；普通 Folder 示例中就是当前读取的一张图片；
- 当前会话：当前用户本次登录会话中已完成序列号/检测单元的汇总；每个已完成序列号最多增加一个 Pass/Fail/Error。

### 7.2 核心数字

按以下顺序展示：

1. Total；
2. Pass；
3. Fail；
4. Error。

统计口径：

$$
Total = Pass + Fail
$$

$$
Pass\ Rate = \frac{Pass}{Pass + Fail}\times100\%
$$

$$
Fail\ Rate = \frac{Fail}{Pass + Fail}\times100\%
$$

Error 单独显示且不进入 Pass/Fail Rate 分母，避免系统执行异常被误判为产品不合格。

### 7.3 统计模式

只保留一个模式切换：

- 数量；
- 合格率。

模式与图表建立固定映射：

| 模式 | 主图表 | 必须显示 |
| --- | --- | --- |
| 数量 | 单一饼图 | Pass Count、Fail Count、精确数字和两者分布 |
| 合格率 | 大型圆环图 | Pass Rate、Fail Rate、Total |

数量模式显示通过/不通过饼图，精确数量统一显示在顶部四个统计单元；无有效结果时显示中性灰色空状态。合格率模式继续使用更大的圆环图突出百分比。不再增加独立的 Bar/Pie 开关，避免形成四种无必要组合；Error 在两种模式中都单独统计，不进入饼图或圆环图。

无已完成结果时，Total 显示 `0`，Pass Rate 和 Fail Rate 显示 `--`，图表显示空状态而不是 100%。

### 7.4 辅助统计

首页不重复显示结果、耗时和会话卡片。历史趋势、查询和导出未在此页实现。

### 7.5 更新规则

- 完整检测单元完成后，数字和图表使用同一个统计快照原子更新；一个序列号对应的图片只有在全部普通项完成后才计入一次；
- Running 中的测试项不提前计入 Pass 或 Fail；
- Error 发生时只增加 Error Count；
- 复位当前未完成运行时，不删除已保存的当前会话统计；
- 新登录会话开始时当前会话清零。

## 8. 底部状态条与日志

验收版本上方显示最新状态，例如：

`10:24:33 · Label Alignment passed · Duration 326 ms`

默认仅显示状态条，点击“运行日志”展开 140 px 日志区，包含时间、级别、测试项/事件和消息，底部显示日志文件路径。再次点击收起。

## 9. 状态与反馈优先级

从高到低排列：

1. 系统 Error 与阻塞性图源错误；
2. 当前 Test Run 总体结果；
3. 当前测试项 Result；
4. Test Sequence 进度；
5. 当前会话汇总统计；
6. 采集参数和普通运行日志。

阻塞性错误必须明确说明对象、原因和建议操作，例如：

`Camera 01 disconnected. Check the cable, then select Retry.`

不得只显示错误码或红色图标。

## 10. 视觉 Token

下列色值为概要设计阶段的可替换 Token。正式施耐德品牌规范提供后，应进行对照和可访问性校验后替换，不在业务组件中散落硬编码颜色。

| Token | 暂定值 | 用途 |
| --- | --- | --- |
| `color-bg-app` | `#F6F7F5` | 应用背景 |
| `color-bg-surface` | `#FFFFFF` | 主要内容面 |
| `color-bg-selected` | `#EDF8EF` | 当前项和选中行浅底色 |
| `color-border` | `#D9DED8` | 分隔线和输入框边界 |
| `color-text-primary` | `#252A2E` | 主要文字 |

## 11. 字体、间距和组件形态

### 11.1 字体

建议 Windows 字体栈：

```text
Segoe UI Variable, Segoe UI, Microsoft YaHei UI, sans-serif
```

| 层级 | 建议字号 |
| --- | ---: |
| 页面标题 | 20–22 px |
| 区域标题 | 16–18 px |
| 正文和表格 | 14–16 px |
| 元数据和辅助说明 | 12–13 px |
| 关键统计数字 | 24–32 px |

当前 Operator 实现按该层级放大：页面/当前项标题为 18–22 px，区域标题为 15 px，正文与关键值为 12–14 px，辅助文字为 11–12 px，统计数字为 20–32 px。复杂规则详情区固定在图像下方并提供局部纵向滚动，字号放大后不得把标题顶出或挤占实时图像。

### 11.2 间距

使用 4 px 基础网格，主要间距为 8、12、16、24 和 32 px。列表行和表单字段必须共用统一垂直节奏。

### 11.3 组件形态

- 圆角以 4–6 px 为主；
- 分区优先使用间距、对齐和细分隔线；
- 阴影仅用于需要浮层关系的菜单、日志抽屉，以及操作员三枚执行按钮的 1–2 px 克制按压层次；
- 不使用卡片套卡片；
- 不使用胶囊形统计卡和装饰性徽章；
- 主按钮全页同一时刻原则上只保留一个。

## 12. 登录与角色入口

v0.6.0 启动后先显示中文登录窗口。左侧为产品识别和角色说明，右侧为用户名、密码、登录状态和本地验收账户辅助入口。

- 登录成功后才创建操作员工作台；错误密码或禁用账户不得进入主界面；
- Admin 顶部显示“管理员”，同时显示“导入测试序列”和“测试序列设置”；图源在向导第 02 步配置，关闭或导出后返回同一操作台；
- Operator 顶部显示“操作员”，保留“导入测试序列”，“测试序列设置”入口使用 `Collapsed`，不参与布局和键盘焦点；
- 两种角色都使用同一测试执行与统计工作台，避免产生两套执行逻辑；
- 本地账户密码不回显，账户文件只保存带随机盐的 PBKDF2-SHA256 哈希；
- 固定验收账户只服务本地验收，生产版本需补充改密、锁定、审计和外部身份源。

## 13. 图源配置入口

Operator 工作区不显示独立“图源设置”按钮，也不允许操作员临时切换图源。Admin 统一从“测试序列设置”的第 02 步配置图源：

- 图片文件夹与视频文件夹互斥选择，并分别保留路径；
- USB 摄像头和工业相机仅显示灰态“待开发”；
- 当前只确认前端路径和信息架构，视频读取、相机枚举、连接和现场 Runtime Source Policy 留待功能阶段。

旧 `InputSourceSettingsWindow` 仅作为 v1 兼容代码和自动验收窗口保留，不再是操作台可导航入口，不能用于解释当前前端信息架构。

## 14. Admin 测试序列设置页面

### 14.1 V2 顺序向导

V2 将复杂分区页改为顺序向导。顶部步骤条用于定位和回看，5 个步骤在可用宽度内作为一组整体居中，只有总宽度确实溢出时才启用横向滚动；下面的大内容区一次只回答一个问题。2026-08-21 评审确认后的前端 v0.2 保留以下 5 个顶层步骤：

1. 项目信息：项目、工位、型号和版本；
2. 选择图源：图片文件夹与视频文件夹二选一；USB 摄像头和工业相机仅保留“待开发”入口；
3. 导入模型：建立项目模型库，可连续添加或删除全部 ONNX/PT 模型文件；当前前端任务类型只显示目标检测、姿态/时序和图像分割，已识别标签通过加号、减号和直接编辑维护；
4. 测试步设置：左侧按执行顺序呈现测试步，列表从上到下依次执行，可用上下箭头调整。目标检测、图像分割和姿态测试步都只显示“基本信息、自定义函数”；目标检测与图像分割从基本信息打开逐 Label 配置弹窗，姿态在首次选择姿态/时序模型时自动打开动作顺序弹窗；不再设置独立“测试序列调用计划”界面；
5. 应用与导出：汇总项目、图源、模型、测试步及其从上到下执行顺序、检测标签、姿态动作、自定义函数和运行约定；主按钮把当前配置直接应用到当前操作台，次按钮弹出保存位置并导出一个 `.sequence.json` 逻辑文件及引用模型。两个动作独立，导出不关闭设置窗口或切换操作台。

图源选择页使用四张整卡控件。“图片文件夹”和“视频文件夹”属于同一单选组，鼠标点击卡片任意位置即可二选一；选中卡显示浅绿背景、深绿边框和选中图标，切换时另一张卡立即取消选择，不能同时保留。两种可选图源共用下方文件夹路径与“浏览文件夹”入口，但标题、说明和路径按类型切换并分别保留。USB 摄像头和工业相机卡使用灰态并明确标注“待开发”，当前不可选择，也不显示设备参数面板。该状态只用于前端评审，不代表图片读取、视频解码/连续取帧、DirectShow/厂商 SDK 枚举、相机连接、实时预览或运行策略已接入。

模型导入页采用“左侧项目模型列表、右侧当前模型设置”的双栏结构。左侧始终显示项目内全部模型及其文件、类型和标签/动作数量，列表顶部并排显示“添加模型 / 删除当前”两个文字按钮；删除当前模型时同时清理依赖它的未交付测试步，允许把模型库删到空。任务类型不再提供图像分类，保留目标检测、姿态/时序和图像分割。选择 ONNX 文件后尝试读取元数据标签；已识别标签列表提供加号、减号和直接编辑，读取失败时仍可手工维护，不再使用“自动识别/手动填写”下拉框。当前前端只显示名称、任务类型、模型文件和标签；Version、SHA-256、Adapter、Label ID、Runtime Profile 与 Contract 等内部字段保留在数据层。解释性说明移入标题或控件 ToolTip，不常驻占用内容区。

默认演示型号为生产代码样式的 `FAN-A01`，只放置一个“风扇检测”测试步；该步绑定 `fan.onnx` 的 6 个 Label，并以 AND 组合标签、黑线、白线和三种反向类别规则。Label 规则在界面统一称为“检测标签”，不拆成 6 个并列测试步。所有测试步都参与序列执行与产品总判定，因此基本信息不显示“是否必选 / 设为必选项”。检测类型提供“目标检测（单张图）/姿态动作（连续帧）/图像分割（单张图）”三项。新增测试步或点击“选择模型”后打开独立模型弹窗，只列出当前检测类型兼容的模型；没有模型时引导返回第 03 步。目标检测与图像分割共用逐标签配置流程：选定模型后按标签重建并打开标签列表，点选标签后配置整图或 ROI、判定方式、数量与成立结果。置信度阈值位于判定区最底部、非必填，空值按 `0.5`；其余必填项带红色 `*`。保存后回到标签列表，重新编辑只替换同名项。图像分割仍只完成配置占位，真实掩膜输出与判定语义留待功能阶段确认。

每个检测标签默认只保留一个名为 `ROI` 的区域。ROI 配置必须先导入一张参考背景图，随后才允许在预览区用十字光标拖拽标注；未导入背景图时保存与拖拽均被阻止。底图使用 `Uniform` 维持原始宽高比，灰色留白不参与框选；画布只对实际图像视口做坐标换算，并把导入图像的像素宽高写为 ROI 参考尺寸。默认无图草稿仍使用 `640 × 480`；不足 4 个参考坐标单位的小框不覆盖上一次有效结果，Esc 或捕获丢失也恢复旧值。该配置会进入导出的 sequence；当前受支持的 Detection 兼容链可执行 ROI 规则，其他任务类型继续按运行时门禁处理。

姿态不再作为独立顶层步骤，也不再拥有常驻“动作设置”页签，而是与目标检测、图像分割并列的测试步类型。在基本信息选择姿态/时序模型后，界面自动弹出动作顺序配置；动作卡显示连续编号并提供前移、后移、添加和删除，模型、Label、最短保持和最大等待按当前动作分别配置。保存后弹层关闭并在基本信息显示顺序摘要与“重新编辑动作顺序”入口；取消或按 Esc 恢复打开前的内容。姿态动作顺序只属于当前测试步内部；多个测试步的执行顺序直接采用左侧列表从上到下的顺序，每个测试步在当前前端只出现一次。

“自定义函数”取代旧前端中的“触发与运行”演示表单。页首提供当前测试步下拉框，可不返回基本信息直接切换；每个 Test Step 分别配置函数类型、函数名称、Python 文件、延时和说明，不同测试步之间不共用这些字段。导入的测试步若无函数，名称、路径与说明均保持空白，允许确认并以 null 重新导出；填写部分函数信息后仍需补全必要字段，延时始终校验。当前只保留概念和界面，不执行 Python，也不提供工厂函数样例；后续已经做好的函数仍需等待工厂方清单和调用契约后接入。

设置端既可把当前草稿直接应用到同一窗口的操作台，也可生成可交付的 sequence 逻辑文件及其引用模型；其他操作端仍只负责导入并执行。直接应用和导入都会校验 schema 与当前兼容运行契约，任何一项不满足都保留原操作台并失败关闭；可移植导入还校验文件存在性与模型 SHA-256。该兼容链不等于 PLC、IO、相机 SDK、视频、自定义函数或其他模型任务已经接入。

顶部步骤卡区分“待设置、正在设置、已完成”；只有本页可见必填项校验通过并点击“下一步”确认后才变绿，直接跳步不补齐状态，已确认内容失效时立即退绿。测试步页签按当前检测类型动态显示并作为一个顶层步骤统一校验。所有必填字段显示红色 `*`，置信度是明确的可选例外；说明性提示统一放入深色 ToolTip，信息图标提供至少 22 × 22 命中区，约 150 ms 后显示并保持 20 秒。底部最终页显示“上一步 / 导出 Sequence 与模型 / 应用到当前操作台”。

### 14.2 V1 功能基线

`v1.0.0` 标签中的 v0.6.0 应用在管理员工作台顶部提供入口“测试序列设置”，打开独立窗口并按以下七个分区组织：

1. 常规：项目、工位、测试序列名称/版本、默认延时、绑定图源、帧输入策略和发布标记；
2. 模型与标签：模型名称、版本、ONNX/PT 格式、任务类型、文件路径、“读取标签”、标签来源和“编号=名称”标签映射；
3. 目标与绑定：目标名称、主绑定模型和输出标签；
4. 规则与 ROI：普通检测项新增/删除、AND/OR、数量指标、比较方式、阈值、置信度、成立结果、全图/ROI 和坐标；
5. 姿态序列：线性动作画布、动作条件、姿态/时序模型绑定、保持时间、最大等待和顺序调整；
6. 输入源：当前测试序列的图源绑定与运行策略摘要；
7. 用户与权限：展示本地账户、Admin/Operator 会话隔离和仍待开发的生产账户边界。

新增普通检测项时，系统将其追加到序列末尾，并基于第一个已有的有效普通视觉 Target/Model Binding 建立全图默认规则：Detection/Segmentation 使用“在场数量等于 1”，Classification 使用“是否存在等于 1”，条件成立时均为通过；只有 Pose/Temporal 绑定或没有有效绑定时明确阻止新增。删除普通检测项时同步删除其规则、压缩剩余测试项顺序，并保留至少一个测试项。上述变更先进入配置草稿，只有“校验并保存”成功后才写入项目配置。

ROI 编辑区使用当前图像作为背景，既可手工录入 X1/Y1/X2/Y2，也可在图像上拖动框选。保存时统一调用 schema v1 配置校验，存在阻塞错误时不写入 JSON；保存成功后主工作台重新加载。ONNX 的“读取标签”会回填 `metadata_props` 标签并显示输入/输出张量；满足静态 `Float[1,3,H,W]` → 端到端 `Float[1,N,6]` Detection 契约时工作台显示“真实推理”，不满足时显示具体阻塞原因。PT 及其他 ONNX 任务仍依赖后续适配器。

## 15. 页面状态

Operator 主页面至少覆盖：

| 状态 | 页面行为 |
| --- | --- |
| Loading | 显示模型和图源加载进度，“开始”禁用 |
| Ready | 图源正常，“开始”可用 |
| Running | 当前项高亮，图像持续更新，图源选择和“复位”禁用 |
| Pass | 显示总体 Pass，保留全部测试项结果 |
| Fail | 显示总体 Fail，并突出失败项和实测原因 |
| Error | 显示系统错误和恢复操作，不产生虚假 Pass/Fail |
| Stopped | 保留已完成项，未执行项保持 Pending 或标记 Stopped |

## 16. 前端实现门禁

前端进入编码前，至少完成以下检查：

1. 页面区域、字段和状态已经过评审；
2. 数据来源和更新时机明确；
3. Operator 与 Admin 权限边界明确；
4. 默认、空、加载、禁用、Fail、Error 和断连状态均有定义；
5. 统计口径与后端一致；
6. 设计 Token 可集中替换；
7. 不存在左侧、中部和底部三份重复测试表；
8. Test Sequence 执行和统计在同一页面同时可见；
9. 图源在顶部可识别，运行时切换受 Admin 策略控制；
10. 设计评审通过后方可开始页面实现。
