| 项目 | 内容 |
| --- | --- |
| 文档版本 | v1.1 |
| 文档状态 | Operator 主界面布局评审通过；Test Sequence Setting V2 前端待评审 |
| 编制日期 | 2026-08-07 |
| 关联需求 | [软件需求规格说明](./软件需求规格说明.md) |
| 实现状态 | v0.6.0 功能基线已冻结为 `v1.0.0`；V2 已完成八步 WPF 前端原型、项目多模型库、有序检测项编辑与目标/姿态类型联动，尚未接入配置读写、真实模型导入、校验和发布 |

## 1. 设计结论

Operator 主界面采用**单页三栏结构**。测试执行与全局统计始终在同一页面同时可见：

- 左侧回答“执行到哪一步、每一步是什么状态”；
- 中部回答“当前看到了什么、按什么标准判断、实测结果是什么”；
- 右侧回答“当前运行或当前会话总体检测情况如何”；
- 顶部持续显示 Project、Test Sequence 和当前图源；
- 底部保留运行状态和紧凑实时日志；完整历史查询后续进入独立页面。

本设计不使用游戏化视觉，不使用深色仪表盘，不把统计拆为独立页面，也不在不同区域重复堆放同一批测试信息。

## 2. 设计目标

1. 操作工在一个页面内完成图源确认、启动测试、观察当前项和查看统计。
2. 当前测试项、总体结果和系统异常具有明确且互不混淆的视觉层级。
3. 浅色、淡雅、克制，同时保留施耐德软件测试工具的工业感和绿色识别色。
4. 高信息密度但不拥挤，避免完整表格、图表和日志同时争夺注意力。
5. Admin 配置能力与 Operator 执行能力分离，避免操作工误改检测标准。

## 3. 页面信息架构

### 3.1 页面区域

| 区域 | 基准尺寸 | 是否固定 | 主要职责 |
| --- | ---: | :---: | --- |
| 顶部应用栏 | 高 56 px | 是 | Project、Test Sequence、图源、用户和时间 |
| 左侧 Test Sequence | 宽 260 px | 是 | 全序列进度、测试项状态和执行控制 |
| 中部检测工作区 | 剩余宽度，建议不小于 680 px | 否 | 图像、ROI、检测叠加和当前项详情 |
| 右侧全局统计 | 宽 360 px | 是 | 数量、比率、图表和辅助统计 |
| 底部状态与日志 | 高 96 px | 是 | 最新运行状态、紧凑实时日志和日志文件路径 |

1440 px 宽度下，左右固定栏合计约 620 px，其余宽度优先留给中部图像。窗口缩放时，中部区域先自适应；右侧统计不得隐藏，左侧项目名称可省略显示但状态图标必须保留。

### 3.2 信息唯一归属

| 信息 | 唯一主展示区域 | 其他区域允许展示的摘要 |
| --- | --- | --- |
| Test Sequence 全部测试项 | 左侧 | 中部只显示当前项 |
| 当前项标准和实测值 | 中部 | 左侧只显示状态 |
| Pass/Fail 汇总数量和比率 | 右侧 | 中部只显示当前项结果 |
| 当前图源和连接状态 | 顶部 | 图像工具条可显示采集参数 |
| 紧凑实时日志 | 底部状态区 | 完整 JSONL 日志保存在本机文件 |

禁止在左侧列表、中部详情和底部日志中同时显示三份完整测试结果表。

## 4. 顶部应用栏

### 4.1 内容顺序

从左到右依次为：

1. 产品名称 `Visual Inspection Test Deployment`；
2. 当前 Project；
3. 当前 Test Sequence 和 Version；
4. 当前图源；
5. 图源连接状态；
6. 当前用户；
7. 当前日期和时间。

### 4.2 图源显示与切换

顶部图源控件使用统一格式：

- Camera：`Camera 01 · Live`；
- Folder：`Folder · Production Images`；
- 正常：绿色圆点和文字 `Ready`/`Live`；
- 等待或警告：黄色图标和可读说明；
- 断开或不可用：红色图标和可操作错误说明。

权限行为：

- 默认采用 Fixed Source，图源控件只读；
- Admin 启用 Runtime Source Switching 后，控件变为下拉选择；
- Operator 只能选择 Admin 已配置、已验证且授权给当前 Test Sequence 的图源；
- 图源只能在测试开始前切换；Running 状态下控件禁用；
- 相机参数、文件夹路径和遍历规则不得在 Operator 页面修改。

## 5. 左侧 Test Sequence 区

### 5.1 顶部摘要

显示：

- Test Sequence 名称；
- 当前进度，例如 `Step 2 of 4`；
- 一条细进度条；
- 当前运行状态，例如 Ready、Running、Stopped、Completed。

### 5.2 测试项列表

每行高度建议为 56–64 px，只显示：

- 顺序编号；
- 测试项名称；
- 状态图标与状态文字。

状态包括：

| 状态 | 展示方式 |
| --- | --- |
| Pending | 灰色空心圆 + `Pending` |
| Running | 绿色进度指示 + `Running`，使用浅绿色行底 |
| Pass | 勾选图标 + `Pass` |
| Fail | 叉号图标 + `Fail` |
| Error | 警告图标 + `Error` |
| Stopped | 停止图标 + `Stopped` |

列表不显示模型、完整标准、坐标和详细实测值，避免与中部当前项详情重复。

### 5.3 执行控制

左侧底部固定放置：

- `Start Test`：唯一高强调主按钮；
- `Stop`：次级按钮，Running 时可用；
- `Reset`：次级按钮，Running 时禁用。

按钮位置在不同 Test Sequence 长度下保持不变。

Folder 图源且全部启用项均为普通检测项时，`Start Test` 代表一次文件夹批量任务：按图源排序逐张显示图片，并让每张图片执行完整普通 Test Sequence。底部状态/日志显示 `当前文件序号/总数 · 文件名 · 结果`；左侧仍只展示当前图片正在执行的测试项，不额外复制一份图片列表。含姿态项时 Folder 继续作为连续帧流，不显示为逐图批量统计。

## 6. 中部检测工作区

### 6.1 图像工具条

只保留与当前观察直接相关的控件：

- Show Overlays；
- Fit / 100%；
- 当前分辨率；
- 当前 FPS；
- 当前采集状态。

不得在工具条加入模型管理、相机高级参数或统计设置。

### 6.2 图像画布

图像画布占中部主要空间，显示：

- 实时相机帧或当前文件夹图片；
- Detection Bounding Box；
- ROI；
- Label 与 Confidence；
- Pose Keypoints 或当前动作提示；
- 必要的缩放、适应窗口和隐藏叠加层功能。

叠加层要求：

- 线宽和文字背景保持克制，不遮挡关键图像；
- ROI 与检测框使用不同线型或标签，不只依靠颜色区分；
- Fail 目标可以使用红色框，但不得使整个画面大面积变红；
- Error 不作为检测框结果显示，应在状态区域解释原因。

v0.6.0 已显示真实 Folder 帧，并按原始像素比例合成当前规则 ROI、真实 ONNX 或验收清单 Detection Bounding Box、Target 名称和 Confidence；同一空间框同时用于规则计数，避免显示与判定分叉。Pose Keypoints 和 Overlays 开关仍未实现，当前不伪造。

### 6.3 当前测试项详情

图像下方设置固定高度的当前项详情区，字段为：

| 字段 | 示例 |
| --- | --- |
| Item | Label Alignment |
| Standard | X/Y Offset ≤ 2 mm |
| Measured | X = 0.12 mm；Y = -0.08 mm |
| Model | Label_Align_v2 |
| Delay | 100 ms |
| Result | Pass |
| Duration | 326 ms |

当一个测试项包含多条 Rule 时，详情区可按行展示 Rule，但只展示当前测试项，不扩展为整个 Test Sequence 表格。

## 7. 右侧全局统计区

右侧统计栏全高固定显示，不因测试项切换、图像缩放或日志展开而消失。

### 7.1 统计范围

顶部使用两段式切换：

- Current Run；
- 当前会话。

默认选择当前会话。

定义：

- Current Run：当前检测单元的一次 Test Sequence 结果；纯普通 Folder 批量中，一个检测单元就是一张图片；
- 当前会话：当前用户本次登录会话中已完成检测单元的汇总。纯普通 Folder 批量按图片累计，含姿态项或相机单次执行按完整 Test Run 累计。

### 7.2 核心数字

按以下顺序展示：

1. Total；
2. Pass；
3. Fail；
4. Error。

统计口径：

$$
Total = Pass + Fail
$$

$$
Pass\ Rate = \frac{Pass}{Pass + Fail}\times100\%
$$

$$
Fail\ Rate = \frac{Fail}{Pass + Fail}\times100\%
$$

Error 单独显示且不进入 Pass/Fail Rate 分母，避免系统执行异常被误判为产品不合格。

### 7.3 统计模式

只保留一个模式切换：

- 数量；
- 比率。

模式与图表建立固定映射：

| 模式 | 主图表 | 必须显示 |
| --- | --- | --- |
| 数量 | 横向柱状图 + 下方紧凑饼图 | Pass Count、Fail Count、精确数字和两者分布 |
| 比率 | 大型圆环图 | Pass Rate、Fail Rate、Total |

数量模式利用统计区下半部空白固定显示通过/不通过饼图，并在右侧图例标出精确数量；无有效结果时显示中性灰色空状态。比率模式继续使用更大的圆环图突出百分比。不再增加独立的 Bar/Pie 开关，避免形成四种无必要组合；Error 在两种模式中都单独统计，不进入饼图或圆环图。

无已完成结果时，Total 显示 `0`，Pass Rate 和 Fail Rate 显示 `--`，图表显示空状态而不是 100%。

### 7.4 辅助统计

统计栏底部只展示：

- Last Result；
- Average Cycle Time；
- Session Start Time；
- Error Count。

历史趋势、按天查询和导出不放在 Operator 主页面，进入独立 History 页面。

### 7.5 更新规则

- 完整检测单元完成后，数字和图表使用同一个统计快照原子更新；普通 Folder 批量中的单张图片只有在全部普通项完成后才计入；
- Running 中的测试项不提前计入 Pass 或 Fail；
- Error 发生时只增加 Error Count；
- 复位当前未完成运行时，不删除已保存的当前会话统计；
- 新登录会话开始时当前会话清零。

## 8. 底部状态条与日志

验收版本上方显示最新状态，例如：

`10:24:33 · Label Alignment passed · Duration 326 ms`

下方固定显示紧凑 Live Log，包含时间、级别、测试项/事件和简短消息，右侧显示 JSONL 文件路径。该区只承担运行观察，不复制测试项结果表；历史筛选和可展开抽屉列为后续增强。右侧统计栏始终可见。

## 9. 状态与反馈优先级

从高到低排列：

1. 系统 Error 与阻塞性图源错误；
2. 当前 Test Run 总体结果；
3. 当前测试项 Result；
4. Test Sequence 进度；
5. 当前会话汇总统计；
6. 采集参数和普通运行日志。

阻塞性错误必须明确说明对象、原因和建议操作，例如：

`Camera 01 disconnected. Check the cable, then select Retry.`

不得只显示错误码或红色图标。

## 10. 视觉 Token

下列色值为概要设计阶段的可替换 Token。正式施耐德品牌规范提供后，应进行对照和可访问性校验后替换，不在业务组件中散落硬编码颜色。

| Token | 暂定值 | 用途 |
| --- | --- | --- |
| `color-bg-app` | `#F6F7F5` | 应用背景 |
| `color-bg-surface` | `#FFFFFF` | 主要内容面 |
| `color-bg-selected` | `#EDF8EF` | 当前项和选中行浅底色 |
| `color-border` | `#D9DED8` | 分隔线和输入框边界 |
| `color-text-primary` | `#252A2E` | 主要文字 |
| `color-text-secondary` | `#667078` | 次要文字 |
| `color-brand-green` | `#3DCD58` | 施耐德绿色识别和强调 |
| `color-green-text` | `#237A35` | 浅色背景上的 Pass 文字 |
| `color-fail` | `#C9403A` | Fail 图标和重点数值 |
| `color-fail-bg` | `#FBEDEC` | Fail 浅背景 |
| `color-error` | `#C88700` | Error 与 Warning |
| `color-error-bg` | `#FFF6DD` | Error 浅背景 |
| `color-pending` | `#8A9198` | Pending 和禁用状态 |

使用约束：

- 大面积背景只使用暖白、白色和极浅灰/浅绿；
- Brand Green 只用于主操作、当前项、连接正常、ROI 和 Pass 强调；
- Pass、Fail、Error 必须同时使用文字与图标，不能只靠颜色；
- 白色文字与绿色按钮的组合必须在最终 Token 确认时通过对比度检查，必要时使用更深的交互绿色变体；
- 禁止霓虹绿、渐变绿和大面积纯绿色面板。

## 11. 字体、间距和组件形态

### 11.1 字体

建议 Windows 字体栈：

```text
Segoe UI Variable, Segoe UI, Microsoft YaHei UI, sans-serif
```

| 层级 | 建议字号 |
| --- | ---: |
| 页面标题 | 20–22 px |
| 区域标题 | 16–18 px |
| 正文和表格 | 14–16 px |
| 元数据和辅助说明 | 12–13 px |
| 关键统计数字 | 24–32 px |

### 11.2 间距

使用 4 px 基础网格，主要间距为 8、12、16、24 和 32 px。列表行和表单字段必须共用统一垂直节奏。

### 11.3 组件形态

- 圆角以 4–6 px 为主；
- 分区优先使用间距、对齐和细分隔线；
- 阴影仅用于需要浮层关系的菜单或日志抽屉；
- 不使用卡片套卡片；
- 不使用胶囊形统计卡和装饰性徽章；
- 主按钮全页同一时刻原则上只保留一个。

## 12. 登录与角色入口

v0.6.0 启动后先显示中文登录窗口。左侧为产品识别和角色说明，右侧为用户名、密码、登录状态和本地验收账户辅助入口。

- 登录成功后才创建操作员工作台；错误密码或禁用账户不得进入主界面；
- Admin 顶部显示“管理员”，并显示“测试序列设置”和“图源设置”；
- Operator 顶部显示“操作员”，两个设置入口使用 `Collapsed`，不参与布局和键盘焦点；
- 两种角色都使用同一测试执行与统计工作台，避免产生两套执行逻辑；
- 本地账户密码不回显，账户文件只保存带随机盐的 PBKDF2-SHA256 哈希；
- 固定验收账户只服务本地验收，生产版本需补充改密、锁定、审计和外部身份源。

## 13. Admin 图源设置页面

图源的完整配置不直接嵌入 Operator 工作区。v0.6.0 使用管理员顶栏入口“图源设置”打开独立窗口；目标信息架构仍为：

`Test Sequence Setting > Input Source`

### 13.1 模式选择

页面顶部使用 Folder / Camera 两段式选择。

Folder 模式至少配置：

- Folder Path 与 Browse；
- Supported Formats；
- Include Subfolders；
- Sort Order；
- Invalid File Behavior；
- Loop Playback；
- Pose Sequence Frame Interval；
- 图片预览和 Validate Source。

Camera 模式至少配置：

- USB Camera (DirectShow) / Industrial Camera (Adapter)；
- Adapter；
- Device；
- Resolution；
- Pixel Format；
- Frame Rate；
- Trigger Mode；
- Grab Timeout；
- Live Preview、Test Connection 和 Validate Source。

v0.6.0 已实现 Folder 全部列出的配置项、首帧预览、“校验图源”和保存。校验结果会区分“真实 ONNX Runtime 已就绪”“仅 detections.json 验收清单就绪”和“两者都不可用”。Camera 已显示并可保存 Adapter、Device、Resolution、Frame Rate 与 Grab Timeout；因为 DirectShow/厂商适配器尚未安装，页面明确显示中文阻塞状态，不提供虚假的连接成功或 Live Preview。

### 13.2 Runtime Source Policy

目标版本由 Admin 在图源设置页选择：

- Fixed Source：默认值，Operator 不能切换；
- Allow Operator to Switch：从已验证图源中勾选允许列表。

配置必须在 Test Sequence 发布前验证通过；测试记录保存实际使用的 Source ID 和 Source Type。

v0.6.0 配置模型与常规设置页已支持 `Fixed` / `OperatorSelectable`，默认示例为 `Fixed`；获准图源列表仍待开发。

## 14. Admin 测试序列设置页面

### 14.1 V2 顺序向导

V2 将复杂分区页改为顺序向导。顶部步骤条用于定位和回看，下面的大内容区一次只回答一个问题；底部仅保留“上一步”和“下一步”。步骤数量来自实际配置流程，不固定为参考图中的 5 步；当前前端原型采用 8 步：

1. 项目信息：项目、工位、测试序列名称和版本；
2. 选择图源：图片文件夹、USB 摄像头或工业相机；
3. 导入模型：建立项目模型库，可连续添加多个 ONNX/PT 模型；每个模型独立设置名称、任务类型、文件以及“从模型导入标签/手工标签”；
4. 编排检测项：用加号新增、减号删除和上下移动按钮建立执行顺序；每项填写名称、目标检测/姿态动作类型、必选/可选状态和模型绑定；
5. 检测内容：目标检测显示标签与全图/ROI，姿态动作显示有序动作画布及动作加减排序；
6. 判定条件：目标检测显示数量规则，姿态动作显示最短保持和最大等待时间；
7. 运行参数：毫秒延时、运行时图源策略和发布选项；
8. 检查完成：集中显示检测项顺序、必选状态、目标/姿态类型和其他摘要，并允许点击顶部步骤返回修改。

图源选择页的“图片文件夹、USB 摄像头、工业相机”均使用整卡单选控件。鼠标点击卡片任意位置即可选择；选中卡显示浅绿背景、深绿边框和选中图标，其他卡恢复中性白色，视觉状态必须与实际 `IsChecked` 一致。

模型导入页采用“左侧项目模型列表、右侧当前模型设置”的双栏结构。左侧始终显示项目内全部模型及其文件、类型和标签/动作数量，通过加号继续添加、通过减号删除当前模型，选中项使用浅绿背景和深绿边框；右侧只编辑当前模型的必填字段，并支持目标检测、姿态/时序、图像分类和图像分割类型。不同模型的数据互不覆盖；后续检测项的“绑定模型”下拉框直接读取同一模型集合。删除已被检测项引用的模型时先提示改绑，避免产生悬空选择。

姿态不再作为需要整项目选择或跳过的独立步骤，而是与目标检测并列的测试项类型；一个 Test Sequence 可以按顺序混合两类检测项。检测项列表始终显示两位顺序号、检测类型和“必选项/可选项”，加号、减号、上移和下移均使用系统图标并提供 ToolTip。设置区采用左侧有序列表、右侧当前项表单的双栏卡片，主操作在首屏可见。

目标检测项选择 ROI 后，右侧预览区使用十字光标并直接接受鼠标左键拖拽。按下后开始新矩形，移动时矩形与左侧 `X1/Y1/X2/Y2` 实时同步，松开后确认；当前前端原型按 `640 × 480` 参考坐标映射。点击“重新框选区域”会切换为 ROI 并在底部显示明确提示；不足 4 个参考坐标单位的误点/小框不覆盖上一次有效结果，框选中按 Esc 或丢失鼠标捕获也恢复上一次结果。此交互当前只保存于窗口内存，背景仍是前端占位预览，不读取真实图源、不写入项目配置。

判定条件页下方的“最终判定”必须由当前输入实时生成，不使用固定示例句。目标检测的检测目标直接读取当前检测项所绑定模型的标签，并把全图/ROI、当前 ROI 坐标、数量等于/范围/大于及数量值翻译成完整句子；选择数量范围时显示最小值和最大值，顺序错误时直接显示原因并阻止下一步。姿态检测摘要同步当前动作、最短保持和最大等待时间。此处仍是窗口内前端状态，不代表规则已经持久化或进入真实 Runner。

顶部步骤卡区分“待设置、正在设置、已完成”，在窗口宽度不足或后续步骤增多时允许横向滚动。“已完成”不是访问历史：只有本页必填校验通过并点击“下一步”确认后才变绿；点击顶部卡直接跳到后续步骤时，被跳过的步骤保持待设置；已确认步骤的必填内容后来失效时立即退回未完成。最后确认要求此前所有步骤均为有效完成状态。所有必填字段在标签后显示红色 `*`；专业概念和加减排序操作旁提供可悬停 ToolTip，说明字段用途及操作结果。内容区保持浅色、克制、施耐德绿色识别色，不使用游戏化图标或动效。V2 前端评审阶段使用明确的“不会保存配置”标识；模型库、按钮、输入框和选择状态可以操作，但不调用项目存储、真实模型文件选择/解析、图源 SDK、校验或发布逻辑。

### 14.2 V1 功能基线

`v1.0.0` 标签中的 v0.6.0 应用在管理员工作台顶部提供入口“测试序列设置”，打开独立窗口并按以下七个分区组织：

1. 常规：项目、工位、测试序列名称/版本、默认延时、绑定图源、运行时图源策略和发布标记；
2. 模型与标签：模型名称、版本、ONNX/PT 格式、任务类型、文件路径、“读取标签”、标签来源和“编号=名称”标签映射；
3. 目标与绑定：目标名称、主绑定模型和输出标签；
4. 规则与 ROI：普通检测项新增/删除、AND/OR、数量指标、比较方式、阈值、置信度、成立结果、全图/ROI 和坐标；
5. 姿态序列：线性动作画布、动作条件、姿态/时序模型绑定、保持时间、最大等待和顺序调整；
6. 输入源：当前测试序列的图源绑定与运行策略摘要；
7. 用户与权限：展示本地账户、Admin/Operator 会话隔离和仍待开发的生产账户边界。

新增普通检测项时，系统将其追加到序列末尾，并基于第一个已有的有效普通视觉 Target/Model Binding 建立全图默认规则：Detection/Segmentation 使用“在场数量等于 1”，Classification 使用“是否存在等于 1”，条件成立时均为通过；只有 Pose/Temporal 绑定或没有有效绑定时明确阻止新增。删除普通检测项时同步删除其规则、压缩剩余测试项顺序，并保留至少一个测试项。上述变更先进入配置草稿，只有“校验并保存”成功后才写入项目配置。

ROI 编辑区使用当前图像作为背景，既可手工录入 X1/Y1/X2/Y2，也可在图像上拖动框选。保存时统一调用 schema v1 配置校验，存在阻塞错误时不写入 JSON；保存成功后主工作台重新加载。ONNX 的“读取标签”会回填 `metadata_props` 标签并显示输入/输出张量；满足静态 `Float[1,3,H,W]` → 端到端 `Float[1,N,6]` Detection 契约时工作台显示“真实推理”，不满足时显示具体阻塞原因。PT 及其他 ONNX 任务仍依赖后续适配器。

## 15. 页面状态

Operator 主页面至少覆盖：

| 状态 | 页面行为 |
| --- | --- |
| Loading | 显示模型和图源加载进度，Start 禁用 |
| Ready | 图源正常，Start 可用 |
| Running | 当前项高亮，图像持续更新，图源选择和 Reset 禁用 |
| Pass | 显示总体 Pass，保留全部测试项结果 |
| Fail | 显示总体 Fail，并突出失败项和实测原因 |
| Error | 显示系统错误和恢复操作，不产生虚假 Pass/Fail |
| Stopped | 保留已完成项，未执行项保持 Pending 或标记 Stopped |

## 16. 前端实现门禁

前端进入编码前，至少完成以下检查：

1. 页面区域、字段和状态已经过评审；
2. 数据来源和更新时机明确；
3. Operator 与 Admin 权限边界明确；
4. 默认、空、加载、禁用、Fail、Error 和断连状态均有定义；
5. 统计口径与后端一致；
6. 设计 Token 可集中替换；
7. 不存在左侧、中部和底部三份重复测试表；
8. Test Sequence 执行和统计在同一页面同时可见；
9. 图源在顶部可识别，运行时切换受 Admin 策略控制；
10. 设计评审通过后方可开始页面实现。
